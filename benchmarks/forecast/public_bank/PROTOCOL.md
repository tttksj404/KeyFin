# 공개 실제 은행 거래 예측 검증: 고정 프로토콜 v1

이 문서는 정답 파일 생성·열람 및 후보 실행 전에 고정한다. 변경하면 새 실험 버전으로 취급한다.

## 데이터와 주장 범위

- PKDD'99 Berka의 과거 체코 은행 계좌 거래를 사용한다. 통화는 CZK다.
- 원본 미러 revision `77e9972a1ead107e5f42a91dd989d587bff055a4`.
- `trans.asc` SHA256: `75ab2f39df9d79d79c5c900de90ddd28248b689f214598ac9fa2ff0f574a70d2`.
- `account.asc` SHA256: `58d7f50abd72e9b1a5568346f74bb54cd71224ee1db9f09a27d7cac563f38cc6`.
- 거래에서는 account_id/date/type/amount만 읽는다. 계좌 파일에서는 account_id/date만 읽는다.
- 타깃은 **총 계좌 출금**이다. 소비·순현금흐름·잔액·한국 고객 예측 정확도가 아니다.
- 문서가 정의한 VYDAJ만 출금, PRIJEM은 입금이다. 문서가 정의하지 않은 type이 있는 계좌는 전 기간 제외한다. VYBER를 출금으로 추정하거나 0으로 치환하지 않는다.
- 이 제외는 전체 원본의 자료 품질을 기준으로 한 후향적 코호트 정의다. 미래에도 지원 type만 존재하는 계좌로 한정되는 선택 편향이 있다.
- 거래일만 있으므로 거래일에 관측 가능했다고 가정한다. available_at/수집 지연/계좌 폐쇄 정보가 없어 과거 시점의 실제 이용 가능성을 보증하지 않는다. 기록 없는 날은 0이며 폐쇄 이후와 무거래를 구분할 수 없다.
- 익명 계좌 단위 분할이며, 한 고객의 복수 계좌가 서로 다른 분할에 있을 가능성을 배제하지 못한다.
- Chronos 사전학습에 공개 Berka 자료가 포함되었는지 확인되지 않았다. 이번 분할은 이번 fine-tuning의 계좌·시간 누수를 통제한다.
- 원본 재배포 권리는 확인되지 않았다. 원자료·개별 예측·식별자를 git에 올리지 않는다.

## 계좌·시간 분리

1. 지원 type만 있고 개설일이 1997-01-01 이하인 계좌를 모집단으로 삼는다.
2. ASCII `berka-r12-v1:` + 정규화한 정수 account_id의 SHA256 오름차순으로 정렬한다.
3. 처음 200계좌는 평가, 다음 100계좌는 개발, 나머지는 학습이다. 실행 산출물에는 해시 계좌키만 보관한다.
4. 학습 자료는 학습 계좌의 1997-01-01~1997-12-31 일별 출금 365개다.
5. 개발 기준일은 1998-01-31 / 1998-03-31 / 1998-05-31; 평가 기준일은 1998-07-31 / 1998-09-30 / 1998-11-30이다.
6. 입력은 기준일을 포함한 과거 365일, 정답은 기준일 **다음 날**부터 7일 또는 30일까지 원장 출금 합계다.
7. 기준일 사이 30일 정답 기간은 겹치지 않는다. 같은 계좌·기준일의 7일과 30일은 겹치므로 사례들을 독립 표본으로 취급하지 않는다.
8. model_inputs.json, development_truth.json, evaluation_truth.json을 분리한다. GPU에는 model_inputs.json만 전달한다. 선택 단계는 evaluation_truth.json을 읽지 않는다.

## 고정 후보와 학습

- 최근 28/90/365일 일평균 × 기간.
- 과거 365일 요일 평균과 전체 평균을 50:50 혼합한 일별 합계.
- 과거 365일의 같은 일자(day-of-month) 평균을 미래 날짜에 대응한 합계.
- 위 동일일자 평균과 최근 90일 평균의 50:50 혼합.
- Chronos-2 base: 일별 평균 예측의 음수를 0으로 제한한 합계 / 과거 일별값을 누적한 시계열의 미래 종점 중앙값에서 관측 마지막 누적값을 뺀 값(하한 0).
- Chronos-2 full fine-tuning: 학습 계좌만 사용, 128 steps, batch 64, context 365, prediction length 30, min_past 60, seed 712. learning rate 1e-6 / 3e-6 두 조건. 일별 계열로 학습하고 일별 평균 예측 합계로만 평가한다.
- 추론 context 365, prediction length 30, batch 64, cross_learning=False. 모든 후보는 점예측이다. 일별 분위수를 더해서 합계 확률구간을 만들지 않는다.
- 개발에서 기간별로 모든 단일 후보와 고정된 50:50 혼합 네 개만 비교한다: recent90+calendar_day, calendar_day+chronos_base_cumulative, recent90+chronos_base_daily, calendar_day+chronos_ft128_lr3e6_daily. 추가 배율 보정은 하지 않는다.
- 개발 MAE 최소를 선택한다. 동점이면 후보 이름 사전순으로 결정한다. 비교 기준은 개발에서 선택한 가장 좋은 **보정 없는 단순 기준 후보**다.
- selection.json에 선택·입력·개발 정답·예측 해시를 고정한 다음 별도 평가 명령이 평가 정답을 연다. 평가 결과로 후보를 재선택하지 않는다.

## 지표와 거부 조건

- 기간별 MAE(CZK), WAPE = 절대오차합 / 실제출금합, 평균 bias = 예측−실제(CZK).
- 선택 모델과 기준 모델의 계좌별 모든 기준일을 함께 재표집하는 2,000회 계좌 cluster bootstrap, seed 712, 백분위 95% CI. WAPE 차이 CI도 같은 재표집으로 계산한다.
- 실제 합계 0이면 WAPE는 null이다. 배율 보정은 예측 0 하한을 유지한다.
- 중복 case/계좌, 잘못된 날짜·기간, 미래가 포함된 history, 분할 중복, 미등록/누락/중복 prediction, NaN/Inf/음수 예측·금액을 거부한다.
- 정확한 거래 중복 ID는 입력 파서의 사용 필드 제한 때문에 검사하지 않는다. 원본 고정 해시로 승인된 파일만 허용하며 계좌·날짜별 거래는 여러 건일 수 있다.
- 이 검증은 공개 과거 실제 출금에 대한 후향적 평가다. 동의받은 현재 서비스 고객의 전향적 검증과 독립 인간 감사는 별도로 필요하다.
