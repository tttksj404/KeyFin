# R14 코칭 연결·응답·예측 검증

2026-09-14. 이전 R13 이후의 구현과 실행 증거를 구분한다. **금융 개념 답변, 기능 연결, 실제 미래 예측 정확성은 서로 다른 평가다.** GPU 요청이 성공하거나 규격 시험을 통과했다고 고객의 미래 잔액을 정확히 맞힌 것으로 집계하지 않는다.

> 범위 주의: 이 문서의 앱·Spring·TypeScript 연결 결과는 당시 통합 실험이며 현재 AI MR에서 제외된다. 현재 제공 범위는 `ai/coaching`의 독립 Python API와 그 시험·문서다.

## 시험 기준

**연속 흐름 시험**은 독립 DB와 별도 API 프로세스를 실제로 실행한다. 원본 Twin 생성 → 결제 → 코칭·알림 조회/ack → 같은 대화에서 일반 질문·코칭 이유·월말 예측·위험 → 추가 거래 → 취소·잔액 갱신 → 같은 대화 재질문 → API 프로세스 종료/재시작 → GET·멱등성 순서다. 자연어 질문에 미리 정한 `analysis`를 주입하지 않는다. 라우팅 채택과 설명 채택은 따로 기록한다.

독립 산술 기준은 초기 확정 소비 2,000원, 첫 50,000원 결제 후 52,000원, 12,000원 추가 후 64,000원, 첫 결제 취소 후 14,000원이다. 봉투 잔액은 입력한 결제·수정에 따라 100,000→50,000→38,000→88,000원이며 계좌 잔액 1,488,000원은 별도 잔액 이벤트의 값이다. 기대값을 FDT 계산 결과에서 복사하지 않는다. 이 검사는 이벤트 반영·회계 계약의 검사이고 미래 예측 오차 평가는 아니다.

**금융·개인 질문 시험**은 공식 27주제와 범위 밖/최신 정보/자료 부족/개인 조회/후속 질문을 고정한 개발 회귀다. 질문마다 HTTP, 응답 상태, 선택한 근거 ID 또는 독립 금액, 라우터·작성기 출처, 저장 GET, 대화 이력을 확인한다. 여러 검사 통과를 여러 고객 또는 독립 질문의 수로 바꾸어 세지 않는다. 짧은 후속 질문의 주제가 유지돼도 같은 근거 문장을 다시 보여 준다면 심화 설명 개선이라고 집계하지 않는다.

**예측 검증 API 시험**은 실제 팀 FDT의 예측을 고정하고 시험용 시각을 앞당겨 이후 거래 20,000+6,000원을 입력한 뒤, 별도 원거래 합산 26,000원과 비교한다. 실고객 미래가 경과한 실험은 아니다. 늦은 취소·정정으로 고정한 실제값이나 건수가 바뀌면 새 metrics는 409로 거절하고 과거 정산 기록은 보존한다. 해당 기간 밖의 일반 거래 추가는 평가를 무효화하지 않는다.

추가 독립 검토에서는 알림을 일반 사용자 토큰으로 호출하는 역할 불일치와 재접속 후 출처·기간 표시가 사라지는 결함을 발견했다. 알림 전용 역할 토큰으로 분리하고, assistant 메시지와 원본 답변 참조를 원자적으로 저장해 앱이 다시 조회하도록 수정했다. Python 실제 ASGI 라우트에서 user 세션은 200, 같은 user의 알림 조회/ack는 403/403, notification 역할은 200/200을 확인했다. 이 역할 시험은 TestModel을 사용하며 GPU 추론 시험에 합산하지 않는다.

현재 AI MR에서 제외된 당시 앱 실험에서는 TypeScript·ESLint·고정 잠금 파일 설치·최종 Expo web export가 통과했다. 홈까지 확대한 테스트는 50건 통과 후 열린 비동기 핸들로 종료되지 않아 중단했고, 최종 코칭 28건은 종료 코드 0이었다. 브라우저 연결 실패와 URL 정책 차단으로 실제 데스크톱·모바일 렌더는 확인하지 못했다. 이 결과는 현재 AI MR의 구현·검증 분모에 포함하지 않는다.

## 점수와 날짜를 읽는 법

- HTTP 성공률: 서버 요청이 처리됐는지. 답이 맞았는지와 다르다.
- 라우터 채택: GPU가 허용된 의도를 반환했는지. 템플릿 대체와 분리한다.
- 근거 선택/개인 조회: 해당 고정 질문에 필요한 자료와 금액이 나왔는지. 금융 전반 정답률이 아니다.
- MAE: 동일 사용자·동일 예측 기간의 중앙값 예측과 확정 소비의 절대 차이 평균, 원 단위.
- WAPE: 절대 오차 합계 ÷ 실제 소비 합계. 실제 합계가 0이면 수치를 만들지 않는다.
- 편향: 예측−실제의 평균. 양수는 과대, 음수는 과소 예측이다.
- WIS80·포함률·구간 폭: P10~P90의 오차·실제값 포함 여부·불확실성 크기를 함께 본다. 넓은 구간으로 포함률만 높인 결과를 개선으로 채택하지 않는다.

예측 기간은 기준일 마감 다음 날부터 종료일 마감까지다. “이번 달”의 요청 범위가 월초부터여도 미래 예측 시작일은 기준일 다음 날이다. 앱은 `forecast_start/forecast_end`를 표시한다. 달력의 월·윤년은 반영하고 공휴일 출금 조정·음력 윤달 지원은 주장하지 않는다.

## 남은 완료 조건

실제 DB 이벤트에서 카드 정산·계좌 이체·봉투 잔액을 어떻게 변환할지의 서비스 원천 계약, 운영 사용자별 인증 설정, 실제 앱과 푸시 전달, 오너 리뷰와 develop 통합은 별도 근거가 필요하다. 실고객 예측 성능은 고정한 예측이 만기된 뒤 실제 거래·잔액과 비교해야 한다. 합성 시험이나 공개 해외 원장 결과로 이를 대신하지 않는다.

코드와 실행 증거를 별도 검토했으며 발견한 두 연결 결함까지 수정했다. 직접 외부 감사 호출 경로가 없어 Fable5 감사 자료는 따로 작성했고 최종 외부 감사 판정은 대기한다. 자체 검증과 외부 감사 승인을 동일하게 표시하지 않는다.

AI 실행 코드와 계약은 [flow](../benchmarks/coaching/flow/README.md), [금융·개인 질문](../benchmarks/coaching/knowledge_response/README.md), [외부 호출 인계 계약](app-integration.md), [예측 검증 API](forecast-validation.md), [구조도](architecture.md)에 있다. 원문 응답·DB·로그·wheel은 `artifacts/`에 보관하고 저장소에 업로드하지 않는다.
