# 실제 고객 예측 검증과 AI 코칭 잔여 작업

**다음 개선 대상은 실제 거래로 평가한 FDT 소비 예측과 코칭 사용 흐름입니다.** 합성 질문 144/144건과 엔진 연결 회귀 32/32건은 경로·응답 계약의 통과 결과이며, 실제 고객의 미래 금액을 맞힌 비율이 아닙니다. 현재 수치 예측 비교에서는 FDT를 대체할 근거를 얻지 못했습니다.

2026-09-14에 `feature/ai-coaching`의 `cc914c3` 소스, 보관된 실행 결과, Jira **코칭(AI) 에픽 S15P21A408-21**의 하위 업무를 대조해 이 계획을 작성했습니다. 이후 [R12 답변 개선과 공개 실제 은행 원장 실험](answer-forecast-improvement.md)을 실행했습니다. 해당 보고서는 새 실행의 결과이고, 이 문서는 현재 한국 고객 검증을 위해 남은 계약과 절차입니다. 기존 구현·실험의 상세 근거는 [검증 결과](validation.md), 호출 구조는 [AI·FDT 구조도](architecture.md)에 있습니다.

## 현재 결과로 판단할 수 있는 것

| 근거 | 실제로 확인한 내용 | 확인하지 못한 내용 |
| --- | --- | --- |
| 합성 질문 144건·엔진 회귀 32건 | 지정된 의도·응답 규격에 대한 기존 검사 | 고객 미래 지출·잔액의 정확도 |
| R7 실제 추론 연결: 24개 시나리오, 206 HTTP, 612/612 검사 | 거래·취소·코칭·조회 등 개별 계약과 실제 FDT·LLM 연결 | 한 세션에서 상태 변경과 서비스 재시작까지 이어지는 전체 사용 흐름 |
| 같은 실행의 생성 41/41 HTTP 200 | 추론 서버가 요청에 응답함 | 문장 27개 중 LLM 채택은 20개, 대체는 7개. 판정 5/5·경로 9/9 채택과 구분해야 함 |
| R11 로컬 470개 통과, 실제 차트 14건 | 구현 회귀, 예측 12건의 GPU 근거 선택과 종료 기간 2건 처리 | 금융 예측 정확도, 전문가 코칭 품질, 동시 부하 성능 |
| R7 미래 소비 비교: 11개 후보, 336개 사례 | 합성 SEED의 미래 원장 소비를 대상으로 예측 오차 비교 | 실고객, 독립 비공개 시험, 90일 미래, 장기 운영 |

R7 연결 시험은 정상·경계·오류 주입 사례를 포함합니다. 위 채택·대체 합계는 실행 관측값이며 정상 요청만의 코칭 품질 점수가 아닙니다. 이 계획의 최초 작성에서는 새 GPU 실행을 하지 않았지만, 후속 R12에서는 실제 GPU 실행 전후와 전체 테스트를 다시 검증했습니다. R12의 GPU 경로는 fault 메타데이터를 주입하지 않으므로 문장 4/27 대체를 자연 발생 모델 출력 거부로 구분합니다.

R7은 **합성 인물 4명 × 봉투 7종**을 사용했습니다. 한 명씩 제외하는 네 fold에서 나머지 세 명의 6월까지 학습하고 7월에 선택·구간 보정을 했으며, 제외한 사람의 8월을 평가했습니다. 기준일별 7·14·30일 및 월말 중 미래 관측이 완성된 사례를 합친 수가 336개입니다. 서로 겹치는 기간이 있으므로 336명의 독립 고객처럼 취급하면 안 됩니다.

| 같은 336개 사례의 후보 | WAPE ↓ | MAE ↓ |
| --- | ---: | ---: |
| 현재 FDT | **61.42%** | **92,033원** |
| 전체 이력 일평균 | 66.21% | 99,207원 |
| 요일·전체 평균 혼합 | 64.96% | 97,331원 |
| Chronos-2 기본 누적 예측 | 72.72% | 108,960원 |
| Chronos-2 추가 학습 128 steps | 70.17% | 105,146원 |
| TimesFM 2.5 누적 예측 | 86.83% | 130,102원 |

FDT의 평균 편향은 **−64,447원**으로 과소 예측 방향입니다. MAE 92,033원은 **한 사람의 한 봉투·한 예측 기간**에서의 평균 절대오차이며, 전체 월 지출 오차가 아닙니다. WAPE 61.42%는 실제 소비 합계 대비 절대오차 합계이고 `100 - WAPE`를 정확도로 해석하지 않습니다. 추가 학습은 두 조건 × 네 fold, 총 8회 실행했지만 FDT보다 낫지 않았습니다.

80% 예측 구간의 포함률은 보정 후 75.00%에서 86.61%로 높아졌지만, 평균 폭도 149,583원에서 314,505원으로 넓어지고 정규화 WIS는 0.5137에서 0.5576으로 악화했습니다. 이 보정은 채택하지 않았습니다. 자세한 산식·11개 후보·재현 절차는 [예측 실험 프로토콜](../benchmarks/forecast/README.md)에 있습니다.

## 먼저 예측할 대상과 정답을 고정한다

소비 예측, 계좌 잔액, 예산 사용률은 서로 다른 결과입니다. 세 수치를 같은 “정확도”로 합치지 않습니다.

| 대상 | 정답과 평가 단위 | 필요한 자료 |
| --- | --- | --- |
| 미래 소비 | 사용자·봉투·기간별 확정 소비 합계, 사용자 전체 소비는 별도 집계 | 거래, 분류, 취소·환불 연결, 관측 누락 여부 |
| 미래 계좌 잔액 | 종료 시점에 실제 관측된 계좌 잔액 | 기초 잔액, 입출금, 급여, 카드 대금, 이체, 결제 예정 정보 |
| 예산 사용률 | 동일 기간 실제 소비 / 해당 시점에 편성한 예산 | 편성·수정 시각과 금액, 절약·저축 등 편성 목적 |

Jira 104의 “예산 사용률 100% 근접”은 **편성 정책의 목표**입니다. 절약 때문에 예산을 남길 수도 있으므로 미래 소비 예측값을 예산에 맞추는 보정은 정확도 개선 근거가 되지 않습니다. 과소 예측과 과다 편성을 별도로 계산하고 어느 쪽을 조정할지 결정해야 합니다. 사용률의 허용 범위는 아직 합의된 기준이 없습니다.

현재 서비스의 미래 기간은 **기준일 다음 날부터 종료일까지, 양 끝 날짜 포함**입니다. 예를 들어 2026-09-14 마감 기준 30일은 09/15~10/14, 이번 달 말까지는 09/15~09/30입니다. 시간대와 마감 시각도 고정해야 합니다. 장중 요청에서는 아직 관측하지 않은 당일을 완성된 하루로 취급하지 않도록 데이터 계약을 정해야 합니다.

## 실제 거래로 검증하는 순서

아래 항목은 신규 실고객 평가에 필요한 절차입니다. 현재 제품에 모두 구현되어 있다는 뜻은 아닙니다.

1. **사용 가능한 실제 이력을 확보한다.** 동의·사용 범위가 확인된 비식별 거래와 잔액 이력을 준비하고, 거래 발생일뿐 아니라 서비스가 정보를 알게 된 `available_at`을 보존합니다. 나중에 수신한 취소·정정·급여 정보를 과거 예측 입력에 넣지 않습니다. 거래가 없는 날과 수집하지 못한 날을 구분합니다.
2. **제품과 별도로 정답 원장을 검산한다.** 카드 승인과 대금 출금의 소비 이중 계산, 내부 이체, 부분 환불, 늦은 취소, 분류 변경을 별도 SQL·계산표로 대조합니다. 제품의 분류 함수를 그대로 재사용한 검사는 회귀시험으로 표기합니다. 정답 승인 근거가 없으면 독립 인간 검증으로 집계하지 않습니다.
3. **학습·모델 선택·구간 보정·최종 평가를 분리한다.** 시간 순서로 기준일을 전진시키면서 과거만 입력하고, 사용자도 분리한 별도 시험을 둡니다. 기존 사용자의 다음 기간 예측과 처음 보는 사용자 예측을 각각 보고합니다. 현재 R7의 7월 선택·보정 공유는 신규 최종 평가에 그대로 쓰지 않습니다. 이 방식의 기본은 [rolling-origin 교차검증](https://otexts.com/fpp3/tscv.html)입니다.
4. **고정한 후보를 같은 입력에서 비교한다.** 현재 FDT, 단순 기준, 신규 후보 모두 동일한 기준일·자료·기간에서 평가합니다. 모델·코드·입력·설정의 해시를 고정하고 정답 누락이나 중복 예측은 점수 계산 전에 거절합니다. 최종 시험 결과를 보고 수정했다면 그 시험은 회귀 자료로 전환하고 새 최종 시험을 준비합니다.
5. **평균과 함께 실패 집단을 확인한다.** 봉투·기간·급여 형태·신규 사용자·관측 부족별 오차와 편향을 기록합니다. 기간이 겹치므로 사용자와 달력 블록의 의존성을 반영한 재표집으로 후보 간 차이의 신뢰구간을 구합니다. 독립 사용자·기간이 부족하면 탐색 결과로만 보고합니다. 필요한 표본 수는 파일 행 수가 아니라 파일럿의 오차 변동과 탐지하려는 개선 폭으로 정합니다.
6. **오늘 저장한 예측을 미래 실제값과 비교한다.** 고객에게 노출하지 않는 shadow 평가에서 예측을 먼저 고정하고 7·14·30일 또는 월말이 지난 뒤 정산합니다. 90일 평가는 실제 90일이 지난 사례만 포함합니다. 코칭을 노출한 경우 노출·수락 여부도 남깁니다. 코칭으로 소비가 바뀐 사례의 오차를 자연 상태 예측 실패와 그대로 섞지 않습니다.

평가 저장 계약에는 최소한 다음 정보가 필요합니다. 개인정보 원문과 거래 원문은 이 문서나 Git에 저장하지 않습니다.

| 기록 | 필수 정보 |
| --- | --- |
| 예측 등록 | `prediction_id`, 비식별 사용자 키, `as_of`, 입력 수신 마감, 시작·종료일, 봉투/계좌 범위, 모델·FDT·설정·입력 해시, 점 예측·분위수 또는 경로, 자료 부족 상태 |
| 실제값 정산 | 예측 ID, 실제 금액, 원장 버전·정답 규칙 버전, 정산 시각, 완결/미완결 상태, 정정 이력 |
| 비교 보고 | 후보별 동일 사례 수·제외 사유, 기준 대비 오차 차이와 신뢰구간, 기간·사용자군별 지표, 지연·실패·대체, 채택 또는 기각 이유 |

현재는 연구용 입력 동결·결과 평가기가 있습니다. 실제 이벤트의 수신 시점 보존, 실고객 예측 등록 및 미래 실제값 정산 운영은 추가 연결·검증이 필요합니다.

## 먼저 비교할 개선 후보

FDT가 소비 금액을 계산하고 LLM이 의도·판정·설명을 담당하는 책임은 유지합니다. 큰 LLM이나 배치 크기 변경만으로 소비 예측 오차가 줄었다고 판단하지 않습니다.

| 순서 | 후보와 바꾸는 부분 | 채택 판단 |
| --- | --- | --- |
| 1 | 과소 예측 원인 분해: 반복 결제·급여일·요일·관측 부족·취소 처리, 예측 시점에 알려진 예정 금액 | 정답·입력 누락을 먼저 구분. 봉투·기간별 편향 감소와 전체 오차 동시 확인 |
| 2 | FDT 예측의 제한적 편향 보정 및 이력 가중치 후보 | 검증 자료에서만 학습. 데이터가 적은 사람의 과도한 보정을 억제하고 현재 FDT와 비교 |
| 3 | 소비 발생 여부와 발생 시 금액을 분리하는 모델, 달력·최근 패턴을 사용하는 분위수 회귀 | 지출이 드문 봉투와 큰 단발 지출에서의 이익·손해를 분리 확인 |
| 4 | Chronos-2의 공변량 입력과 실제 이력 기반 추가 학습, 검증에서 선택한 앙상블 | 현재 합성 자료의 추가 학습 실패를 기준선으로 보존. 같은 미사용 미래에서 다시 비교 |
| 5 | 별도 보정 집합에서 예측 구간 보정 | 포함률·폭·WIS를 함께 개선해야 채택. 포함률만 높인 후보는 기각 |

Chronos-2는 공변량과 여러 시계열을 지원하지만 우리 고객 데이터에서의 우위는 미확인입니다. 기능 근거는 [공식 구현](https://github.com/amazon-science/chronos-forecasting)에 있습니다. 예측 시점에 알 수 없는 미래 입력은 넣지 않으며, 미래 공변량의 가용성은 [조건부 예측 설명](https://otexts.com/fpp3/forecasting-regression.html)과 같이 별도로 다룹니다.

새 모델도 후보가 될 수 있습니다. 다만 TimesFM 3.0의 현재 공개 가중치는 [공식 모델 카드](https://huggingface.co/google/timesfm-3.0-pytorch)에 비상업 라이선스로 표시되어 있어 서비스 교체 후보로 바로 채택하지 않습니다. 공개 벤치마크 순위는 이 서비스의 금융 예측 결과를 대신하지 않습니다.

앙상블·계좌 잔액·총소비는 같은 경로의 현금 흐름과 집계 관계를 보존해야 합니다. 일별 P50을 합쳐 기간 P50으로 간주하거나 봉투별 확률을 독립이라고 가정하지 않습니다.

## 채택 기준은 금액 오차와 불확실성을 함께 본다

| 평가 축 | 지표와 용도 |
| --- | --- |
| 점 예측 | MAE(원), WAPE, 평균 편향. 전체 사용자·봉투·기간을 분리하고 사용자 균등 집계와 금액 가중 집계를 함께 확인. 실제 소비 합계 0인 집단의 WAPE는 `null` |
| 예측 구간 | WIS, 80% 구간 포함률, 구간 폭. 원래 FDT의 보정 전 구간과 후보를 같은 사례에서 비교 |
| 잔액 부족 위험 | 예측한 부족 확률과 실제 부족 여부의 Brier score, 합의한 오경보 비용에서의 탐지율. 잔액 정답이 없으면 소비 자료로 대신 계산하지 않음 |
| 코칭 | 의도 선택, 근거 없는 금액·인과 주장, 유효 문장 채택/템플릿 대체, 전문가의 근거·이해도 평가 |
| 서비스 | 요청 실패·지연·동시 부하, 저장·재시작·중복 처리. 숫자 예측 정확도와 별도 보고 |

기존 연구의 “FDT 대비 WAPE 10% 상대 감소, 단순 기준보다 우수, WIS 개선, 기간별 WAPE 악화 5% 이내”는 **프로젝트 실험 제안값**입니다. 산업 표준이나 합의된 운영 SLA가 아닙니다. 실제 고객 평가 전에 허용 금액 오차·오경보 비용·운영 지연 기준을 정하고, 충분한 미사용 고객·기간에서 개선의 신뢰구간과 주요 집단의 악화를 함께 확인해야 합니다. 통과하더라도 이후 데이터 변화에 대한 지속적인 성능을 보장하지는 않습니다.

110의 추가 실행은 **Twin 생성 → 결제 → 코칭·알림 조회/ack → 같은 세션의 설명·위험·월말 질문 → 새 거래·취소·잔액 변경 → 같은 세션 재질문 → 서비스 재시작 → 이력 GET**을 한 사용 흐름으로 연결해야 합니다. 자동 기간 선택은 구조화된 `analysis`를 강제로 넣지 않고 확인합니다. 정상 경로의 실제 LLM 채택과 오류 주입에 따른 대체를 따로 집계합니다.

기존 [실제 HTTP 실행기](../benchmarks/coaching/e2e/README.md)는 24개 시나리오를 검사하지만, [취소 동작](../benchmarks/coaching/e2e/e2e_actions.py) 뒤 [대화 함수](../benchmarks/coaching/e2e/e2e_dialogue.py)는 새 세션을 만듭니다. 취소 전 대화부터 이어진 동일 세션의 검증과 같지 않습니다. [재시작 통합 회귀](../tests/test_api.py)의 `test_full_payment_chat_outbox_restart_and_isolation`은 `TestModel`과 ASGI 전송을 쓰므로 실제 추론 서버를 포함한 서비스 재시작 증거로 집계하지 않습니다. 개별 기능이 고장났다는 판정이 아니라, **요구한 전체 연결을 입증하는 실행 증거가 더 필요하다는 판단**입니다.

우선순위는 110의 연속 흐름 검증을 보강하면서 104의 실제 원장·예산·기준일 계약을 준비하는 것입니다. 이후 104의 고정 평가에서 후보를 비교합니다. 실제 데이터와 미래 정산이 확보되기 전에는 “실제 고객 예측 정확도 확보”나 “최고 성능 달성”으로 완료하지 않습니다.
