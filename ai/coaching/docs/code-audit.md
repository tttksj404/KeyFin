# 코드·검증 경계 재점검: R11

2026-09-11에 운영 코드의 고정값, 금융 입력과 저장, 모델 입출력, 평가 결과 생성 경계를 재점검했습니다. 발견한 오류를 재현한 뒤 수정했고, 리뷰어가 계산 이유와 실패 시점을 따라가도록 한국어 주석과 [코드 리뷰 안내](code-review.md)를 추가했습니다. 모델을 새로 학습하거나 FDT를 교체한 작업은 아닙니다.

## 범위와 방법

시작 시점의 추적 중인 코드 137개 파일을 분류했습니다(서비스 39, 실행 스크립트 5, 벤치마크 34, 테스트 31, 타입 선언 7, 해당 확장자의 vendor 코드 21). 운영 코드의 테스트 입력·벤치마크 직접 import는 0건이었습니다. 이 정적 검사를 근거로 모든 간접 의존성이나 오류가 없다고 단정하지 않고, 금융·런타임·저장·평가 경로를 나누어 추적하고 실제 반례를 실행했습니다.

금액·소비자·날짜가 결과에 고정 삽입되는 경우와 스키마·지원 범위·자원 제한을 구분했습니다. 7개 봉투, 버전 해시, 재현 seed, 계산량·토큰 상한, 코칭 발생 임계값의 이유와 변경 시 검증 항목은 [고정값 표](code-review.md#고정값이-있는-이유)에 있습니다. 예측 정답을 제품 함수나 LLM 출력으로 새로 만들지 않았습니다.

## 재현하여 수정한 운영 문제

| 문제 | 수정 전 반례 | 현재 처리 |
| --- | --- | --- |
| 취소 환불 잔액 초과 | 외부 확정 잔액을 상한까지 조정한 뒤 이전 결제를 환불하면 잘못된 원장을 저장하고 다음 조회가 500 | 차감·환불에 동일 Envelope 검증, 422와 상태 보존, 같은 키로 수정 후 재시도 가능 |
| 숨은 문자로 문구 길이 검사 우회 | 정규화로 지운 문자 때문에 검사 통과 후 원문 Wording 생성에서 예외 | 원문과 정규화 문장 모두 400자 검사, 사유가 있는 대체 안내 |
| 근거 없는 인과·급등 문구 | 근거 없이 “외식비가 급등했으니…” 같은 주장을 채택 | 인과·변화 단정의 보수적 거절 규칙 추가; 모든 의미 오류 방지의 증명은 아님 |
| 스키마 추가 후 입력 초과 | 원래 메시지는 허용 길이지만 응답 스키마를 합친 뒤 500 | 합친 메시지·합계 길이를 먼저 검사하여 413 |
| 비 ASCII 인증·지문 | `compare_digest` 예외로 500 | 잘못된 인증은 401, 프롬프트 지문은 409 |
| 관측액+예측액 합계 초과 | 각각 허용되는 금액의 합이 차트 안전 정수 범위를 넘음 | 중간 합계도 검사하여 422, 금액을 잘라내거나 차트로 저장하지 않음 |
| 입금을 소비로 처리 | `TRANSFER_IN`과 `EXPENSE` 동시 지정 | 팀 FDT 설계와 모순되는 조합을 입력 어댑터에서 422; 나머지 엔진 해석 유지 |

`TRANSFER_IN`의 근거는 고정된 FDT 설계의 입금 분류와 direction 일관성 계약입니다. vendor를 수정하지 않고 신규 입력·이벤트 경계에 적용했습니다. 기존에 저장된 모순된 거래의 일괄 마이그레이션을 수행했다는 의미는 아닙니다.

9월 14일에는 최종 이미지 관찰에서 320px 누적 소비 카드의 큰 금액과 통화 단위가 분리되는 표시 문제도 확인했습니다. 원본 차트 자산은 유지하고 조립 코드의 글자 크기를 화면 폭에 맞게 조정했습니다. 금융 계산이나 저장된 JSON 값을 변경한 것은 아닙니다.

## 재현하여 수정한 평가 문제

| 문제 | 수정 |
| --- | --- |
| 신경망 예측이 하나도 없어도 기준선만으로 평가 완료 | 공통 후보 5개와 추가 학습 2개의 모든 사용자 fold·case 예측을 점수 저장 전에 검사 |
| 실제 소비가 전부 0이면 후보 선택 실패 | WAPE는 `null`, 선택에만 MAE 사용; FDT와 전체 평균 상한 유지 |
| 기록한 파일 해시를 검증하지 않음 | v2에 원본 UTF-8 JSON을 보존하고 해시·파싱값·키 집합·모델 입력 해시 대조 |
| 런타임 ZIP에서 wheel 필수 차트 자산 누락 | Chart manifest와 원본 자산을 포함하고 오프라인 설치까지 검사 |
| 사례 수를 실제 결과와 무관하게 24로 기록 | `Report.cases`의 실제 길이로 기록하고 복원 시 재검사 |
| 같은 case의 정답을 중복 입력하면 마지막 값 사용 | 동일 값·다른 값 모두 중복 정답을 점수 저장 전에 거절 |

새 평가기는 v1을 거절하므로 [원본 worker JSON에서 재export](../benchmarks/forecast/README.md)해야 합니다. 해시를 함께 고칠 수 있는 작성자로부터 정답의 진실성을 보증하는 서명 체계는 아니며, 독립 인간 승인 원장을 대신하지 않습니다.

## 확인한 결과와 해석

- 전체 테스트 **470개 통과**, Ruff 통과, 서비스 소스 범위의 엄격 타입 검사 오류·경고 0건입니다. 기존 Starlette `BlockingPortal` 폐기 예정 경고 1건은 남습니다.
- 주석만 보강한 단계의 운영 소스 44개 파일은 docstring을 제외한 AST가 전후 동일했습니다. 주석 개선을 모델 성능 향상으로 집계하지 않습니다.
- 기존 실제 GPU R7 결과 JSON **27개 원본 해시가 기존 기록과 일치**했습니다. 원문을 v2로 다시 내보내 엄격한 평가기로 재생했고, 11개 후보와 선택 정책의 **12개 점수 보고서가 기존과 완전히 같았습니다**. 네 fold 모두 FDT 선택을 유지합니다. 재학습·새로운 검증셋의 성능 측정은 아닙니다.
- 평가기 반례 검증에서는 실제 준비 runner가 만든 개발 336·평가 336개 사례를 사용했습니다. 신경망이 빠진 묶음은 **6,048개 필수 예측 키 누락**으로 출력 디렉터리 생성 전에 거절했습니다. 별도 합성 예측 fixture 검사는 평가기 계약 시험이며 모델 품질 점수가 아닙니다.
- 실제 HTTP 스모크도 통과했습니다. 모델을 연결하지 않은 로컬 스모크와 실제 GPU 연결 검증은 [검증 결과](validation.md)에 구분합니다.

실제 고객 미래 예측 정확도, 전문가의 코칭 평가, 동시 부하와 자동 재시작 운영, 외부 감사는 완료되지 않았습니다. 이번 근거는 재현한 오류 수정과 기존 계산 보존이며, 모든 하드코딩이나 오류가 없다는 보장이 아닙니다.
