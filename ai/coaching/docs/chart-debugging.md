# 차트 누락 디버깅 보고서 — 2026-09-11, R10

09/03 이후 일별 예측이 보이지 않던 문제를 고친 R9에서, **입력 → FDT → GPU 설명 → 저장·재조회 → 화면**을 추가 점검했습니다. 숫자 계산과 별개로 자료의 한계가 사라지는 문제, 미관측 날짜를 0원 기록으로 만드는 문제를 재현해 수정했습니다.

## 발견한 문제와 수정

| 문제 | 실제 재현 | 수정 후 동작 |
| --- | --- | --- |
| FDT 품질 안내 누락 | 과거 거래가 단 하루인데 FDT는 `SHORT_HISTORY`를 반환하고, 화면·GPU 근거에는 이 경고가 없음 | 이력 일수·경고·정확도 미검증 안내를 `meta.quality`로 전달. GPU에는 전체 안내를, 필수 설명에는 짧은 핵심 한계를 제공 |
| 미분류 금액 설명 누락 | 현재 10,000원 전부가 미분류이면 전체는 10,000원, 7개 카테고리는 모두 0원이지만 차이 설명이 없음 | 현재 미분류 금액을 안내와 표에 별도로 표시하고, 종료 기간의 총소비 열에도 기록 금액을 표시. 미래 미분류 소비 P50은 원본 지표로 안내하며, 전체 P50과 카테고리 합의 차이로 계산하지 않음 |
| 이력 시작 전 날짜의 허위 0원 기록 | 입력은 09/09부터인데 09/01~09/08도 관측 0원으로 그림 | `observation_start` 이전 관측 점을 생성하지 않음. 기간 축은 유지하고 미관측 구간·실제 입력 시작일을 안내 |
| 종료 기간의 분류·정산·고정비 안내 누락 | 종료일에는 예측을 호출하지 않아 미분류·정산 입금 경고가 사라짐. 거래 목록만 재점검하면 모델이 추가한 고정비 경고도 빠짐 | 예측 호출 없이 원래 FDT의 `Twin.model.audit`를 `receipt.observation_audit`에 보존. 기록 소비·미분류 포함·정산 입금 미차감·고정비 제외를 구분 |
| 일부 예산을 전체 예산 미제공처럼 표현 | 기타 예산은 100,000원인데 총계 옆에는 단순히 ‘예산 정보 없음’으로 표시 | 일부 항목만 입력되었으며 전체 합계·전체 사용률을 계산할 수 없다는 안내로 구분 |

수정 과정에서 **짧은 이력 + 미관측 구간 + 미분류**가 겹치면 설명문이 400자를 넘어 HTTP 500이 되는 회귀도 잡았습니다. 400자 제한은 유지하고, 전체 자료 안내와 짧은 설명을 분리했습니다. 10,000원과 입력 상한 1조 원의 조합 사례를 모두 검사했습니다. 새 메타데이터 기본값이 예전 저장 JSON에 덧붙는 회귀도 막았습니다.

## 무엇을 어떻게 검증했나

금액 검증에는 구매 10,000원, 카드대금 출금 10,000원, 고정비 70,000원, 취소 20,000원, 이체 5,000원, 정산 입금 3,000원을 함께 넣었습니다. 이 차트의 계약은 구매시점 변동소비이므로 확인해야 할 현재 소비는 **10,000원**입니다. 카드대금·고정비·취소·이체는 더하지 않고, 원거래와 연결되지 않은 정산 입금은 임의 차감하지 않으며 그 한계를 표시합니다. 이는 미리 정한 산술·분류 계약 검사입니다.

| 검증 | 비교 기준 | 결과 |
| --- | --- | --- |
| 자동 회귀 | 신규 누락·기간·인증·저장·모델 경계 등을 포함한 전체 테스트 | **428개 통과**, Ruff 통과, 서비스 엄격 타입 검사 오류 0 |

| 미래 날짜 | 기준일 다음 날~종료일까지 연속 날짜와 receipt·차트·SVG의 일별 금액 대조 | 서버 14건의 **242개 미래 날짜** 일치. 종료 기간에는 미래 점 없음 |

예측 요청 12건의 순차 POST 시간은 중앙값 **3.158초**, 범위 **2.690~3.647초**였습니다. FDT 계산·토큰 검사·GPU 선택·저장을 포함하며, 동시 부하나 속도 개선 실험은 아닙니다. 실제 채택 설명은 150~285자였습니다. 종료 기간 2건은 이 통계에서 제외했습니다.

최종본의 로컬 19건과 서버 14건을 각각 **1280·390·320px**에서 열어 **99화면·297회 상호작용**을 확인했습니다. 날짜·금액·전체 품질 안내·미관측 구간·미분류의 현재/종료 금액, 일별 표 열기·종료일 포커스·카테고리 선택을 실제 DOM과 저장 JSON으로 대조했습니다. JavaScript 오류·페이지 가로 넘침·외부 요청·대조 실패는 0건입니다. 별도 리뷰에서도 수정된 종료 화면을 직접 렌더링해 확인했습니다.

## 해석과 남은 검증

이번 결과는 **지원하는 입력의 금액·날짜·자료 한계가 빠짐없이 전달되는지**에 대한 검증입니다. 기존 FDT의 수치 계산, 시뮬레이션 방법, 학습된 모델은 바꾸지 않았습니다. 일별 평균의 합과 전체/항목별 P50은 서로 다른 통계이므로 같을 필요가 없습니다.

SEED와 합성 사례는 실제 고객의 미래 예측 정확도를 입증하지 않습니다. 새로운 고객군·거래 수신 지연·독립적으로 승인된 금융 정답·실제 미래 잔액 비교와 외부 Fable5 감사는 남아 있습니다. 기존 Starlette의 `BlockingPortal` 폐기 예정 경고 1건도 유지됩니다. 이번 결과를 모든 입력에서 누락이나 장애가 없다는 증명으로 해석하지 않습니다.
