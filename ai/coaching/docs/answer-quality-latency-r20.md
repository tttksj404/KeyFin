# 답변의 내용과 동시 요청 지연 개선 (R20)

2026-09-15. 기존 의도·JSON 계약 통과만으로 답변이 질문에 필요한 내용을
제공했다고 판단할 수 없어, **사용자에게 실제 표시된 본문**을 별도로 평가했다.
대상은 일반 금융 질문이며, 미래 소비·잔액의 예측 오차 실험과 구분한다.
예측 모델 추가학습의 결과는 [R19 예측 평가](forecast-retraining-r19.md)에 있다.

첫 동결 후보의 vLLM 조합은 기존 vLLM 대비 개발 **5/20→19/20**,
확인 **5/12→10/12**로 개선됐다. 확인 평가에서 남은 세후 계산 분류 오류,
예산 판단 목적 누락과 개발 질문의 상태 불일치를 수정한 최종 v4는
**알려진 32질문·96응답의 회귀 기준을 모두 통과**했다.

최종 v4 vLLM은 변경 전 Transformers 대비 단일 요청 중앙값이 **37.44% 감소**했으나,
동시 8건은 **P95 10.93% 감소 / 중앙값 13.98% 증가**로 결과가 혼재한다.
배치 상한 8도 중앙값 개선 기준을 못 넘겨 채택하지 않았다.
답변은 개선했지만 동시 처리 속도의 최적화가 끝났다고 보지 않는다.

## 변경한 코드

첫 동결 비교는 LLM의 가중치와 금융 근거 27개를 유지하면서 검색·질문 분류·설명 선택을 수정했다.

- 별칭 일치만으로 찾지 못하는 한국어 바꿔 말하기를 승인 본문의 BM25 검색으로 보완한다.
  별칭은 없지만 본문과 겹침이 있는 소규모 목록은 전체를 보여 의미로 선택하게 한다.
  유효 자료 32개 이하에서만 적용하며, 더 큰 목록은 상위 8개를 사용한다.
- “그럼 그건?” 같은 후속 질문은 직전 사용자 주제를 함께 읽고, “복리 대신 리볼빙”처럼
  제외한 주제는 이후 대화에서도 되살리지 않는다.
- 명시적으로 열거한 여러 주제 중 일부만 답한 결과를 검사한다. 이 규칙은 명확한 열거의
  방어선이며, 모든 문장에서 설명 누락을 자동 판정하는 의미 평가기는 아니다.
- 개념과 최신 금리·개별 약관·정확한 계산이 섞인 질문은 설명 가능한 승인 문단을 제공하고
  `needs_source`와 부족한 조건을 표시한다. 현재 금리·세율·개인 금액은 생성하지 않는다.
- 근거 입력의 중복 URL·검토일·별칭 메타데이터를 줄인다. 원본 목록과 응답 출처에는
  보존하며, 전체 요청의 실제 tokenizer 검사와 입력 8,192토큰 제한은 유지한다.
- 지시 오염이 섞인 질문도 분류기는 실제 금융 질문의 목적만 JSON으로 반환하게 한다.
  확인 평가에서 발견한 가정의 세후 이자 계산과 개인 거래 예측의 혼동도 추가 수정했다.
- 후속 수정에서는 계산 원리를 설명할 수 있는데도 `needs_source`로 반환하던 상태를 구분한다.
  필수·선택 지출 자료에는 예산 판단의 목적을 한 문장 보완하고 자료 버전을 갱신했다.
  이 설명은 [CFPB 원문](https://www.consumerfinance.gov/consumer-tools/educator-tools/youth-financial-education/teach/activities/budgeting-needs-and-wants/)의
  예산 선택·지출 결정 목적을 2026-09-15에 재확인해 반영했으며, 모델 답변을 사실 근거로 삼지 않았다.

[검색 구조와 범위](knowledge-retrieval.md), `finance_knowledge.py`,
`knowledge_retrieval.py`, `llm_prompt.py` 및 관련 테스트에서 변경을 검토할 수 있다.
FDT 계산·기간·금액 조립과 원천 자료의 권한 경계는 유지한다.

## 무엇을 정답으로 삼았는가

모델 답변을 보기 전에 별도 에이전트가 28질문과 질문별 기준을 작성했고,
이미 재현된 개발 진단 질문 4개를 더해 **개발 20개 / 확인 12개**를 고정했다.
각 질문에는 반드시 설명할 의미 2개와 해서는 안 될 주장 2개가 있다.
공식 출처의 버전이 고정된 설명과 실제 본문을 읽어, 의미별 지원 문장 또는 누락을 기록했다.

사례 하나는 동시 요청 1·4·8건 조건의 **세 응답이 모두** 아래 조건을 만족해야 통과한다.

1. 요구한 핵심 의미를 빠짐없이 전달한다. 필요한 자료가 없어 답할 수 없는 질문은
   어떤 자료가 부족한지 설명해야 하며, 답할 수 있는 개념을 일반 거절문으로 끝내면 실패다.
2. 근거 밖의 확정 사실·금액·보장 주장을 추가하지 않는다.
3. 실제 본문과 출처, 응답 종류와 상태가 일치한다.

근거 ID가 맞거나 HTTP 200이어도 핵심 설명이 빠지면 실패다. 승인 문단의 순서나
ID 집합이 다르더라도 필요한 의미를 실제로 전달하면 그 본문으로 판단한다.
벤치마크 자동 점수기도 ID뿐 아니라 실제 승인 본문과 출처 전달 여부를 검사하도록
고쳤다. 이 자동 검사는 의미 평가를 대신하지 않는다.

개발자는 모든 루브릭을 알고 있고, 작성자·검토자 모두 AI 에이전트다.
따라서 인간 전문가 정답률, 비공개 블라인드 검증 또는 실제 고객 정확도로 부르지 않는다.
개발 응답만 보고 수정한 v2를 동결한 뒤 확인 12개의 응답을 열었다.
여기서 발견한 오류를 수정한 v3·v4의 동일 질문 재평가는 **이미 본 질문의 회귀시험**이다.
그 결과를 새 미공개 확인 성능으로 바꾸어 부르지 않는다.

## 같은 조건의 GPU 비교

모든 실행은 `Qwen/Qwen3.8-27B` revision
`1d4bf0f2ff6012fd82039f2fa52739d0dd7c60c0`, NF4, greedy를 쓴다.
첫 네 조합과 v3는 같은 근거 목록이며, v4는 위에서 설명한 예산 판단 문장만 보완했다.
변경 전 API wheel과 v2 wheel을 각각 Transformers / API 동시성 4,
vLLM / API 동시성 8에 연결해 네 조합을 측정했다. GPU batch 상한은 4다.
가중치 추가학습이나 더 낮은 정밀도로 속도를 얻은 비교가 아니다.

각 실행은 서로 다른 32질문을 동시 요청 1·4·8건에서 한 번씩 보내 **96개 최종 응답**을
수집한다. 세션은 질문별로 새로 만들고, 후속 질문의 준비 대화는 별도 보존한다.
고객 자료는 사용하지 않는다. 같은 준비 대화·스모크·질문 순서를 사용한다.
vLLM의 prefix cache는 끈다. 런타임 버전과 지원 조건은
[R19 실행 환경](performance-forecast-r19.md#추론-실행-환경-비교)에 기록했다.

지연은 loopback HTTP 요청부터 최종 JSON 수신까지이며, 모델 적재·준비 대화·세션 생성·
사전 스모크는 제외한다. 각 조건의 32개 값을 정렬해 `(n−1)×0.95` 위치를 선형 보간한
값이 P95다. 아래 표는 **중앙값 / P95, 초**이며 실패·대체 응답도 제거하지 않았다.

| API / 실행 환경 | 동시 1건 | 동시 4건 | 동시 8건 | 최대 메모리 MiB |
| --- | --- | --- | --- | ---: |
| 변경 전 / Transformers | 3.64 / 4.80 | 10.40 / 30.02 | 17.08 / 30.04 | 19,937 |
| 변경 전 / vLLM | 1.53 / 1.86 | 7.60 / 11.70 | 13.12 / 15.74 | 34,727 |
| v2 / Transformers | 5.06 / 6.03 | 15.14 / 19.81 | 26.92 / 40.04 | 25,903 |
| v2 / vLLM | 2.18 / 2.77 | 10.43 / 15.41 | 14.90 / 21.84 | 36,781 |
| v3 회귀 / vLLM | 2.25 / 2.82 | 10.33 / 16.15 | 18.59 / 23.85 | 36,733 |
| v4 회귀 / vLLM | 2.28 / 2.84 | 10.91 / 14.82 | 19.46 / 26.76 | 36,453 |
| v4 배치 8 / vLLM | 2.26 / 2.88 | 11.75 / 18.63 | 20.13 / 22.43 | 36,425 |

본문을 더 충실하게 선택하는 v2는 동일 실행 환경에서는 입력 처리 비용이 늘었다.
따라서 “프롬프트를 줄여 모든 질문이 빨라졌다”고 주장하지 않는다. 변경 전 Transformers와
v2 vLLM을 비교한 동시 8건 P95 감소는 27.29%지만, 변경 전 vLLM의 일반 거절·설명 누락이
섞인 빠른 응답과도 반드시 함께 비교해야 한다. 속도만으로 변경 전 구현을 선택하지 않는다.

각 조합은 한 차례의 고정 부하 실행이다. 운영 트래픽, 지속 유입, 인터넷 지연, 장시간
안정성이나 모집단 P95 신뢰구간을 입증한 결과가 아니다. HTTP 200은 네 실행 모두
96/96이지만, 질문별 의미 실패와 처리시간 초과는 별도 집계한다.

v3는 가정의 수치 계산 분류만 수정한 중간 회귀다. 확인 09의 세 응답 모두
`finance_education/needs_source`로 올바르게 분류하고 복리·세금·계산 조건을 설명했다.
아직 수정하지 않은 개발 20의 상태 문제는 그대로 남았다. 중간 실행도 삭제하지 않는다.

v4의 동시 8건 P95는 변경 전 Transformers 대비 10.93% 줄었지만,
중앙값은 17.08초에서 19.46초로 13.98% 늘었다. 단일 요청 중앙값은 37.44% 줄었다.
수정 전 vLLM 대비로도 지연이 늘었으므로 **정확도와 모든 지연 지표가 동시에 개선됐다고
주장할 수 없다.** 높은 동시성의 중앙값은 추가 개선이 필요한 부분이다.

### 수정 후 확인과 코드 검사

v4는 일반 가정 계산 분류, 계산 원리의 응답 상태, 승인 자료의 설명 누락을 수정한 버전이다.
v3 대비 바뀐 최종 응답은 9/96개다. 개발 20의 상태·본문 3개, 확인 02의 승인 문장 3개,
확인 04의 과세·계산 조건 안내 순서 3개이며, 다른 87개는 본문·상태·응답 종류가 같다.
참조 정보는 새 목록 버전과 출처 확인일을 별도로 검증한다.

| 수정 후 회귀 | 개발에서 가져온 사례 / 20 | 확인에서 가져온 사례 / 12 | 전체 사례 / 32 | 응답 / 96 |
| --- | ---: | ---: | ---: | ---: |
| v3 | 19 | 11 | 30 | 90 |
| 최종 v4 | 20 | 12 | 32 | 96 |

v4의 각 사례는 동시 1·4·8건에서 모두 핵심 의미·금지 주장·출처·상태 조건을 충족했다.
별도 에이전트가 두 변형의 HTTP·계약 192개와 변형별 출처 블록 120개를 대조했고,
변경한 본문 3종은 실제 구절을 다시 읽어 판정했다. 바뀌지 않은 본문은 사례 ID와
본문 해시가 함께 일치할 때만 기존 의미 판정을 재사용했다.
이 32/32는 이미 노출된 질문의 결함 수정 확인이며 일반 사용자의 정답률 100%가 아니다.

- 전체 서비스 테스트 **856건 통과**. 기존 Starlette 의존성의 deprecation 경고 1개가 남아 있다.
- Ruff 전체 검사 통과, 서비스 basedpyright 오류·경고 0건.
- 별도 코드 검토의 관련 128테스트 통과. 공식 자료 보완과 금액 생성 금지 경계를 재확인했다.
- 실제 TCP API에 시험용 모델을 연결한 기존 41질문·368검사도 통과했다.
  이는 저장·본문 검사기의 검증이며 GPU 모델의 정답률에 합산하지 않는다.
- 마지막 GPU API wheel의 실행 파일 4개가 현재 소스와 byte 단위로 일치하며,
  테스트·실험 결과·로그가 wheel에 포함되지 않음을 확인했다.

### 배치 상한 8은 채택하지 않는다

같은 v4 wheel·가중치·API 동시성 8에서 GPU 배치 상한만 4→8로 늘렸다.
기존 worker와 dispatcher는 4까지만 허용하므로 검증용 복사본의 개수 검사만 확장했고,
저장소의 상한은 4로 유지한다. 패딩 토큰 예산 16,384, FIFO·취소·요청별 입력/출력 한도,
vLLM 최대 sequence 8과 메모리 비율은 바꾸지 않았다. 실제 관측 배치 크기는 1~6이었다.

실행 전에 “동시 8건의 중앙값과 P95 모두 10% 이상 감소, 단일 요청 중앙값 10% 이상
악화 없음, 답변 품질 악화 없음”을 비교 기준으로 정했다. 동시 8건 P95는 **16.19% 감소**했지만
중앙값은 **3.41% 증가**해 기준을 넘지 못했다. 동시 4건 P95도 **25.70% 증가**했다.
좋아진 P95만 골라 기본값으로 적용하지 않는다.

응답 ID·생성시각 두 필드를 제외한 **전체 answer JSON 96/96개**가 v4와 동일했다.
본문뿐 아니라 출처·상태·라우팅·대체 사유까지 비교했으므로 빠른 거절로 지연을 줄인 결과는 아니다.
시험은 한 번씩의 비교이므로 운영 SLO를 보증하지 않는다.

최초 배치 8 시도는 기존 상한 검사에서 요청 0개로 종료했고, 임시 복사본 준비 과정의
로컬 변수명 충돌도 원격 실행 전에 수정했다. 초기 Transformers 실행의 경로 설정 오류와
함께 실패 기록을 보존했으며 성공 응답/지연의 분모에 요청 0개를 섞지 않는다.

## 배포와 MR 범위

GPU 시험은 격리된 임시 API·worker·DB에서 실행했다. 각 실행의 73개 스모크 검사와
종료 후 임시 프로세스 정리·기존 API와 worker의 프로세스 유지 여부를 확인한다.
기존 운영 서버를 vLLM으로 교체했다는 결과가 아니다. vLLM 조합은 약 36 GiB를
사용했으므로 메모리 사용량을 기존 약 20 GiB와 함께 검토해야 한다.

MR에는 `ai/coaching`의 실행 코드·관련 테스트·사람이 읽는 보고서만 포함한다.
프런트엔드·백엔드·공유 설정을 수정하지 않는다. 원문 응답, 실험 로그, wheel, 모델 가중치,
서버 접속 정보와 전용 실행 래퍼는 로컬 `artifacts/` 또는 별도 연구 작업공간에 보관한다.
실험 결과는 아래 원문 해시로 식별하며, 이 보고서만으로 별도 GPU 실험이 자동 재현된다고
주장하지 않는다. 코드의 자동 회귀 검사는 저장소에서 실행할 수 있다.

별도 에이전트의 소스 검토와 본문 판정은 수행했지만, 금융 전문가 또는 외부 Fable5
감사를 완료한 것으로 표시하지 않는다. 원문·판정표와 실패 이력을 포함한 감사 자료는 별도로 보존했다.
