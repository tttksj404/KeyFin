# 과거 연도를 분리한 예측 추가학습·검증 (R19)

2026-09-15. 공개 체코 은행 원장으로 **과거 365일에서 다음 고정 30일 총출금**을
예측하는 추가 실험이다. 질문 의도 정답률·JSON 규격 통과율과 구분하며, LLM이나
FDT가 만든 미래값을 정답으로 사용하지 않는다. 서비스의 팀 FDT는 유지한다.

**이번 추가학습 후보는 채택하지 않는다.** 후보 선택 단계에서 최근 365일 평균
기준모델이 가장 낮은 오차를 보였다. 최종 평가에서는 선택된 기준모델의 오차와
구간 품질을 확인했으며, 예측 성능 향상을 입증한 결과가 아니다.

## 데이터와 기간

원장의 `VYDAJ` 총출금을 CZK 단위로 합산한다. 이체·현금 인출이 포함되어
KeyFin의 한국 원화 7봉투 변동소비나 월 예산 사용률과는 타깃이 다르다.
예측 입력은 기준일 마감까지 365일, 정답은 **기준일 다음 날부터 30일째까지**다.
예를 들어 1996-07-31 기준 정답 기간은 1996-08-01~08-30이다. 8월 한 달 전체를
평가하는 실험으로 표현하면 안 된다. API의 달력상 월말 기간 계약과도 구분한다.

| 용도 | 계좌 | 기준일·기간 | 평가 사례 |
| --- | ---: | --- | ---: |
| 추가학습 | 571 | 1995-01-01~12-31 일별 이력 | 학습 계좌별 365일 |
| 후보 선택 | 150 | 1996-01-31, 03-31, 05-31 | 450 |
| 구간 보정 | 150 | 1996-06-30 | 150 |
| 최종 평가 | 300 | 1996-07-31, 09-30, 11-30 | 900 |

이번 분할의 계좌 교집합은 0이다. 다만 이 계좌들의 다른 연도 이력이 이전
연구에 노출됐으므로 **완전히 처음 본 고객이나 실제 서비스의 전향적 검증**으로
표현하지 않는다. 연구 방법도 이전 실험을 참고해 정했다. 과거 연도에 대한
추가 일반화 점검이며, foundation 모델의 사전학습 자료에 이 원장이 없었다는
보증도 없다. 지원하지 않는 거래 유형으로 계좌를 제외하는 자격 판정에는
미래 메타데이터가 사용되어 회고적 선택 편향이 남는다.

## 미리 고정한 후보·학습

후보는 최근 365일 일평균×30일 기준모델, 원본 Chronos-2, 새 Chronos-2
full fine-tuning 256회다. 기존 연구의 추가학습 체크포인트를 이어 쓰지 않고
원본 가중치에서 다시 시작했다. 학습률 `3e-6`, batch 64, context 365,
min_past 60, seed 715를 고정했다. 일별 이력을 뒤로 끝나는 30일 합계 시계열로
변환하며 관측 이후 값을 입력에 넣지 않는다.

실제 GPU 실행에서 **optimizer update 256/256, 건너뛴 update 0**과 가중치 hash
변경을 확인했다. 학습은 19.44초, Torch 최대 예약 메모리는 3.46GiB였다.
학습·후보 추론 결과 생성은 22.72초, 감독 프로세스가 측정한 전체 실행은
30.48초다. 데이터 준비·전송·CPU 채점 시간은 이 시간에 포함하지 않는다.
1,500사례×3후보=4,500개 예측 중 GPU 모델 추론은 3,000개이고 나머지는
기준모델 계산이다. 4,500개 모두를 GPU 생성이라고 세지 않는다.

실행 환경은 `chronos-forecasting==2.3.1`, `torch==2.7.1+cu128`,
`transformers==5.16.1`, `numpy==2.5.3`이다. 감독 프로세스가 장치 사용을
확인하고 종료 후 학습 프로세스 종료, 장치 반환, 기존 API·worker 보존을 검증했다.

## 정답을 열기 전의 통제

학습 입력·프로토콜·실행 소스·후보 목록을 hash로 고정하고 정답 파일은 GPU에
보내지 않는다. 후보는 선택용 MAE로 한 번 선택하고, 별도 150계좌에서
구간 보정량을 고정한다. 최종 평가에서 exclusive marker를 먼저 만든 뒤
정답 bytes를 한 번 읽어 같은 bytes로 hash 검증과 파싱을 수행한다.
최종 결과를 본 뒤 후보·보정·채택 조건을 바꾸지 않는다.

별도 코드 리뷰가 발견한 문제는 실제 최종 채점 전에 수정했다. 초기 구현의
manifest 해시 검사가 sealed 정답을 미리 읽는 문제, 평가기가 외부 고정
execution lock에 묶이지 않은 문제, 잘못된 lock 경로가 정답 파일을 가리키는
경우에도 읽기 전에 거절해야 하는 문제다. 이 절차 검사는 독립 인간 정답
승인을 대신하지 않으며, 이전 실패 lock과 동결 snapshot도 보존한다.

## 지표가 의미하는 것

| 지표 | 정의·해석 |
| --- | --- |
| MAE | 30일 총출금 예측과 실제 총출금의 절대 차이 평균, CZK. 낮을수록 좋다. |
| WAPE | 절대 오차 합 / 실제 출금 합. 개별 고객 정확도 백분율이 아니다. |
| 편향 | 예측−실제의 평균. 양수는 과대, 음수는 과소 예측이다. |
| 포함률 | 실제값이 예측 P10~P90 안에 들어온 비율. 명목 목표는 80%다. |
| 구간 폭 | P90−P10 평균. 크게 넓히기만 해 포함률을 높인 결과를 구분한다. |
| WIS80 | `(0.5×절대오차 + 0.1×interval_score80) / 1.5`. 구간 폭과 구간 밖 오차를 함께 벌점화한다. |
| paired bootstrap | 계좌 300개를 복원 추출하며 각 계좌의 세 기준일을 함께 유지한다. 2,000회·seed 715로 두 모델 오차 차이의 95% 구간을 구한다. |

900사례를 독립 계좌 900개로 취급하지 않는다. 비교 기준모델에도 같은 방식의
독립 구간 보정을 적용한다. 보정 rank는 `ceil((150+1)×0.9)=136`이며,
과거 이력 기반 규모로 정규화한 양쪽 잔차의 순서통계량을 사용한다.

사전 채택 조건은 전체 MAE 10% 이상 감소, paired WAPE 차이 95% 구간 상단<0,
WIS·절대 편향 비악화, 전체 포함률 75~85%다. 각 기준일과 사전 정의한
저출금 집단도 MAE가 기준보다 5% 넘게 악화하지 않고 포함률이 70% 이상이어야
하며, 저출금 집단의 WIS도 5% 이상 악화하면 탈락한다. 하나라도 미달하면
좋은 평균 수치만으로 모델을 교체하지 않는다.

## 검증 증거와 재현 범위

최종 정답 개봉 전에 별도 에이전트 리뷰에서 봉인 경로·소스 고정·계좌 분리·
계산식·채택 조건을 확인했다. 합성 경계 테스트 32건과 해당 평가 코드의
타입 검사를 통과했다. 이는 사람의 정답 승인이나 외부 금융 감사를 의미하지 않는다.

최종 개봉 후에는 별도 에이전트가 원본 `account`·`trans` CSV를 Python 표준
`csv`와 `Decimal`로 다시 합산했다. 제품·FDT·평가기 함수를 가져오지 않고
900건 정답, 선택·보정, 전체·기준일·저출금 집단, 14개 판정 기준을 비교해
**183/183 비교가 일치**했다. 산술·보고서 불일치 0건이며 FAIL 판정도 같았다.
이는 구현과 분리된 코드 재계산이지 독립 인간 정답 승인이나 고객 예측 검증은 아니다.

Git 제외 실험 보관소에 둔다. 이 MD나 저장소만으로 일회성 실험을 완전히 재실행할
수 있다는 주장은 하지 않는다. 재현자는 위 해시와 일치하는 보관 패키지 및 같은
환경을 받아 별도 출력 위치에서 실행해야 하며, 개봉된 정답은 이후 회귀용이다.
새 후보를 최종 평가하려면 새로 봉인한 평가 구간을 먼저 준비해야 한다.

## 서비스에 적용하려면

Jira S15P21A408-104는 같은 월·봉투의 원래 예산, 당시 예측, 확정 소비를 비교하는
업무다. 이번 CZK 고정 30일 실험으로 한국 고객의 월 예산 예측을 완료 처리하지
않는다. 실제 원천 거래의 수집 시점·범위와 당시 예측을 보존하고, 만기 이후
[월별 평가 API](forecast-validation.md)에서 같은 소비 기준으로 비교해야 한다.
허용 오차·오경보 비용·예산 정책 목표 및 고객군별 악화를 확인한 뒤 적용한다.
실제 고객 미래 정확도와 독립 인간 정답 승인·외부 감사는 별도 남은 조건이다.
