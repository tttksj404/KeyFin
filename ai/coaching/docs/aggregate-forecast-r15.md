# R15 기간 합계 예측 개선 — 2026-09-14

공개 과거 은행 원장에서 **7일 총출금 MAE는 34.47%, 30일은 8.38% 감소**했습니다. 7일 후보는 사전 연구 기준을 통과했고, 30일은 최소 10% 감소 조건에 미달했습니다. 불확실성 구간의 실제 포함률도 목표 80%보다 낮습니다. 이 결과는 한국 고객의 봉투별 소비·잔액 정확도나 운영 배포 승인 근거가 아니며, 서비스의 팀 FDT를 교체하지 않았습니다.

## 무엇을 새로 실험했나

기존 질문 시험은 경로·응답 계약을 검사했습니다. 이번 시험의 정답은 **입력 기준일 이후 원본 은행 원장에 기록된 실제 출금 합계**입니다. LLM이나 FDT가 정답을 정하지 않습니다. 원자료는 R12와 같은 PKDD'99 Berka의 과거 체코 계좌이며 통화는 CZK입니다. 이체·인출을 포함한 총출금이라 한국의 7개 소비 봉투와 같지 않습니다.

일별 예측을 합하는 대신, 입력을 후행 7일/30일 합계로 변환하여 **미래 기간 총액을 직접 예측**했습니다. 예를 들어 1998-07-31 기준 7일 타깃은 08-01~08-07, 30일은 08-01~08-30입니다. 기준일 당일은 미래에서 제외합니다. 달력상의 한 달과 고정 30일을 구분합니다.

각 기간에 다음 20개 후보를 같은 사례에서 비교했습니다.

* 기존 단순 기준 6개: 28/90/365일 평균, 요일 혼합, 동일 일자 평균, 동일 일자와 90일 평균 혼합.
* 산술 후보 5개: 기간 합계 중앙값·절사 평균, 월별 일평균 중앙값, 동일 일자 중앙값, 동일 일자 중앙값과 90일 평균 혼합.
* GPU 후보 3개: Chronos-2 기본 모델과 두 추가학습 조건.
* 혼합 후보 6개: GPU 3개 각각과 동일 일자 중앙값/90일 평균을 50:50으로 결합.

추가학습은 **기본 가중치에서 매번 새로 시작한 full fine-tuning 4회**입니다. 7일/30일 각각 128회 업데이트·학습률 1e-6, 256회·3e-6을 실행했습니다. batch 64, context 365, min_past 60, seed 715를 고정했고 실제 optimizer 갱신 128·256·128·256회, 건너뜀 0회와 서로 달라진 가중치 해시를 확인했습니다. 후보 3개 × 4,000건, 총 12,000개 예측이 생성됐으며 실행은 72.70초였습니다. 학습·추론을 합친 단일 연구 실행 시간이며 사용자 요청 지연이나 동시 처리 성능이 아닙니다.

실행 버전은 torch 2.7.1+cu128, transformers 5.16.1, chronos-forecasting 2.3.1, numpy 2.5.3입니다. 기존 R12의 추가학습 가중치를 재사용하지 않았습니다.

R12의 개발·평가 300계좌를 제외하고 새로 나눴으며 네 집합은 서로 겹치지 않습니다. 다만 새 평가 계좌의 **1997년 이력은 과거 R12 학습에 사용된 적이 있습니다**. 이번 학습에서는 제외했고, 이번 1998년 평가 미래는 R12 개발·평가에서 사용되지 않았습니다. 완전히 처음 본 고객이라고 표현하지 않습니다. 기본 모델 사전학습에 원자료가 포함됐는지는 알 수 없습니다.

미지원 거래 `type`이 원자료의 어느 시점에라도 등장한 계좌는 R12의 자료 선별 규칙에 따라 제외합니다. 이는 미래까지 본 사후 표본 선별이므로, 이 집합이 당시 서비스에 들어올 모든 계좌를 대표한다고 주장할 수 없습니다. `type=VYDAJ` 출금 중 `operation=VYBER` 현금 인출과, 의미가 확인되지 않은 `type=VYBER`를 같은 필드로 취급하지 않습니다.

프로토콜과 입력을 고정한 뒤 GPU에는 과거 입력만 전달했습니다. 개발 MAE로 선택을 저장하고 별도 보정 계좌로 구간을 조정한 다음, 마지막 명령에서 최종 정답을 열었습니다. 결과를 본 후 후보를 재선택하지 않았습니다. 두 기간 모두 **256회 추가학습 모델과 동일 일자 중앙값의 50:50 혼합**이 선택됐습니다. 비교 기준은 개발에서 선택된 7일 `calendar_day`, 30일 `recent365`입니다.

## 최종 평가 결과

각 열은 같은 400계좌 × 3기준일, 1,200사례를 비교합니다. 작은 값이 좋은 오차 지표와 큰 값이 무조건 좋지 않은 구간 지표를 구분했습니다.

| 지표 | 7일 기준 | 7일 선택 | 30일 기준 | 30일 선택 |
| --- | ---: | ---: | ---: | ---: |
| MAE(CZK) ↓ | 1,793.06 | **1,174.98** | 3,757.79 | **3,443.04** |
| MAE 감소율 | — | **34.47%** | — | **8.38%** |
| WAPE ↓ | 71.81% | 47.06% | 38.62% | 35.39% |
| 평균 편향(CZK) | +20.26 | −523.98 | +1,038.18 | −713.37 |
| 보정 80% 구간 포함률 | 72.83% | 76.33% | 75.25% | 69.17% |
| 평균 구간 폭(CZK) | 3,996.64 | 2,654.52 | 10,763.77 | 8,408.44 |
| 보정 WIS80 ↓ | 1,297.37 | 948.55 | 2,482.00 | 2,431.87 |

* **MAE**는 사례마다 예측 총액과 실제 총액의 차이를 절댓값으로 구한 평균입니다. 7일 선택 모델은 한 사례당 평균 1,174.98 CZK만큼 빗나갔다는 뜻입니다.
* **WAPE**는 전체 절대오차 합÷전체 실제 출금 합입니다. 47.06%를 ‘정확도 52.94%’로 바꾸거나, 34.47% 감소를 ‘정확도 34.47%p 상승’이라고 표현하지 않습니다.
* **편향**은 예측−실제의 평균입니다. 선택 모델의 음수 편향은 전반적으로 적게 예측하는 경향입니다.
* **포함률**은 실제 합계가 예측 하한~상한 안에 든 비율입니다. 구간을 무작정 넓혀도 올라가므로 폭과 **WIS**를 함께 봅니다. WIS는 중앙 오차·구간 폭·구간 밖 오차를 같이 벌점으로 계산합니다.

같은 계좌의 세 기준일을 독립 고객처럼 세지 않고, **계좌 전체를 묶어 2,000회 재표집**했습니다. 선택−기준의 paired MAE 차이 95% 구간은 7일 **−773.18~−477.29 CZK**, 30일 **−442.05~−193.64 CZK**였습니다. paired WAPE 차이는 각각 **−31.07~−19.06%p**, **−4.67~−1.95%p**입니다. 이 구간은 고정된 과거 시점과 계좌 표본에 관한 불확실성이며 미래 시점이나 한국 고객의 성능을 보장하지 않습니다.

## 통과와 남은 약점

사전 기준은 MAE 10% 이상 감소, paired WAPE 차이 상한<0, 보정 WIS 악화 없음, 각 기준일 MAE 악화5% 이하였습니다. **7일은 4개 모두 통과, 30일은 MAE 감소 조건만 미달**입니다. 기준을 결과에 맞춰 낮추지 않았습니다.

7일 MAE 감소는 세 기준일에서 37.42%·35.06%·31.37%였지만, 과거 출금이 작은 하위 집단은 6.66% 감소에 그쳤고 WIS는 387.48→398.79로 악화됐습니다. 30일은 16.42%·11.23% 감소 후 마지막 기준일에 **0.053% 악화**됐습니다. 마지막 시점의 30일 구간 포함률은 **60.25%**까지 내려갑니다. 전체 평균 개선만으로 모든 고객·시점이 좋아졌다고 결론내릴 수 없습니다.

두 기간 모두 실제 포함률이 80%에 미달합니다. 다음 연구는 특히 30일·저출금·연말 과소예측과 구간 안정성을 대상으로 해야 하며, 이번 최종 자료를 보고 수정한 모델은 이 자료를 회귀시험으로만 사용하고 다른 미래 관측으로 평가해야 합니다. 현재 원자료에서 남은 짧은 기간을 독립 30일 시험이라고 만들어내지 않습니다.

## 발견한 실패와 평가기 보강

최초 v1은 기본 모델의 7일 추론 2,000건 중 1건에서 P10>P50이 발생하여 학습 전에 중단됐습니다. 정답과 점수를 열지 않은 상태에서 v2에 **중앙값을 유지하고 구간 끝만 넓히는 규칙**을 추가했습니다. v1 실패를 보존했고 입력·프로토콜·실행 디렉터리를 새로 고정했습니다. v2의 비음수 처리 후 구간 역전은 기본 7/30일 1/0건, 128회 학습 20/1건, 256회 학습 20/0건이며 각 분모는 2,000입니다. NaN·무한값·잘못된 shape를 수치로 바꾸지는 않습니다.

평가기 독립 코드 검토에서 GPU 감사 필드와 검증 스키마 불일치, manifest의 필수 정답 해시 누락 가능성, 분할 날짜의 잘못된 라벨, 정확히 10% 감소의 부동소수점 경계 오류를 발견해 최종 평가 전에 수정했습니다. 변경된 정답·불완전한 모델·실제 업데이트 없는 학습 기록·누락된 계좌/기간을 거절합니다. 평가 전 단위시험 31건과 이후 추가한 보정 잠금 변조 시험을 포함해 최종 32건이 통과했으며 이 분모는 예측 정확도와 별개입니다.

최종 결과 이후 다른 검토자가 제품과 연구의 정답 생성 함수를 가져다 쓰지 않고 **stdlib CSV·Decimal로 원거래 1,056,320건을 다시 합산**했습니다. 개발 1,200·보정 400·평가 2,400개 정답은 모두 정수 소액 단위에서 오차 0이었고, 학습·입력 과거값 2,034,510개도 일치했습니다. 선택 모델의 보정 반경·MAE·WAPE·WIS·계좌 신뢰구간·통과 기준을 별도 재계산해 일치 여부를 확인했습니다. 이는 별도 구현을 통한 검증이며 독립 인간의 원장 승인이나 새로운 미래 평가가 아닙니다.

## Jira 104와 제품 연결

원래 월 편성을 별도 불변 계약으로 저장하고, **그때의 미래 예측 / 월 전체 예상 / 확정 소비 / 예산 사용률 / 계획 절약**을 분리하는 [월별 7봉투 평가 API](forecast-validation.md)를 구현했습니다. 원래 편성액이 없으면 현재 봉투 잔액으로 대체하지 않고 예산 사용률을 미집계합니다. 예산 목표에 맞추기 위해 예측값을 강제로 100%에 맞추지 않습니다.

이 평가 기능을 실제 고객의 동의받은 원장·편성·수집 범위와 연결하고, 예측을 먼저 저장한 뒤 같은 달의 미래 소비가 도착하면 검증할 수 있습니다. API 구현·합성 계약 검증을 이미 모인 실제 고객 정확도로 표현하지 않습니다. 사용자가 승인한 편성·서비스 원천 동기화·운영 인증·데이터 보관 조건의 실제 확인이 필요합니다.
