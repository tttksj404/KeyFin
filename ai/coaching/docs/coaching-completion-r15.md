# R15 AI 코칭 구현·성능 개선 결과

2026-09-14, Jira 김성진 담당 AI 코칭 104·110의 추가 작업이다. 원천 거래 동기화, 월별 7봉투 평가, 일반 금융 대화의 표현 누락을 보완했다. 별도 GPU 추가학습 실험에서는 공개 과거 원장의 7일 총출금 예측 오차가 기준 모델보다 34.47% 줄었다. 서비스의 팀 FDT는 유지한다.

> 범위 주의: 이 문서의 Spring·앱·JDBC·JPA·외부 outbox 내용은 당시 통합 실험 기록이며 현재 AI MR에서 제외된다. 현재 제공 범위는 `ai/coaching`의 독립 Python API와 그 시험·문서다.

## 구현한 동작

| 항목 | 변경 후 동작 | 확인 위치 |
| --- | --- | --- |
| 원천 거래 → FDT(과거 외부 연동 실험) | 당시 인증 소유자의 DB 자료를 읽어 신규 결제·취소를 반영하고 JPA 변경과 같은 트랜잭션에 재시도 요청을 저장했다. 이 코드는 현재 AI MR에 포함되지 않는다. | [외부 호출 인계 계약](app-integration.md) |
| 월별 예측 평가 | 기준일 다음날~월말의 미래 오차와 월초~월말의 실제 소비·원래 편성 사용률을 분리한다. | [월별 평가 API](forecast-validation.md#월별-7봉투-평가) |
| 저장·정답 정합성 | 봉투명으로 예측과 정답을 연결하고, 관측 정책·원거래 수정·조회 도중 변경을 감지한다. 손상된 저장 자료를 정상 점수로 계산하지 않는다. | [관측 정답과 수정 감지](forecast-validation.md#원거래-정답과-수정-감지) |
| 일반 금융 대화 | ‘그럼 조금 더 자세히 설명해 줘.’, ‘내 계좌 잔액은 지금 얼마야?’, ‘이번 달 외식 소비를 다시 확인해줘.’를 처리한다. 미지원 은행·금액·제외 조건은 전체 합계로 바꾸지 않는다. | [대화 API](chat.md) |

원래 편성과 계획 절약액을 예측 정답으로 삼지 않는다. 자료가 없으면 금액·사용률을 `null`로 유지한다. 원천 DB에 편성 승인 시각이 없으므로 과거의 사전 승인을 만들어 월별 평가에 넣지 않는다. 25일 시작 예산 주기와 달력월 평가도 서로 바꾸지 않는다.

## 성능 개선의 정답과 분모

이번 연구는 합성 질문의 경로 선택 점수와 다르다. 정답은 공개된 과거 은행 거래의 **예측일 이후 실제 총출금**이며, FDT나 LLM이 만든 정답이 아니다. 학습 1,574계좌, 선택 200계좌, 구간 보정 200계좌, 최종 평가 400계좌를 분리했다. 최종 평가에서는 7일·30일 각각 1,200건을 비교했다.

| 기간 | 기준 MAE → 선택 후보 MAE(CZK) | 오차 감소 | 사전 연구 기준 |
| --- | ---: | ---: | --- |
| 7일 | 1,793.06 → 1,174.98 | 34.47% | 네 조건 통과 |
| 30일 | 3,757.79 → 3,443.04 | 8.38% | 10% 개선 조건 미달 |

MAE는 건별 예측 금액과 실제 금액 차이의 절댓값을 평균한 값이다. 두 기간 모두 Chronos-2를 256회 추가학습한 후보와 같은 달력 일자 중앙값의 50:50 혼합이 개발 자료에서 선택됐다. 실제 GPU full fine-tuning은 4회, 후보 추론은 12,000건 실행했다.

별도 구현자가 원거래 1,056,320건을 다시 읽어 평가 정답 2,400건과 지표를 검산했다. 이는 독립적인 코드 재계산이며 인간의 금융 감사 승인이 아니다. 실제 80% 예측구간 포함률은 7일 76.33%, 30일 69.17%였고 일부 집단의 구간 점수는 악화했다. **한국 고객의 소비·잔액 정확도, 모든 고객군의 개선, 서비스 FDT 교체를 입증하지 않는다.** 전체 프로토콜·비교 후보·신뢰구간·악화 사례는 [연구 보고서](aggregate-forecast-r15.md)에 있다.

| 검사 | 결과 | 실제로 확인한 범위 |
| --- | --- | --- |
| Python 전체 | 813/813, 104.14초 | 최종 제품 코드의 API·저장·수치·기간·오류 복구·연구 평가기 회귀 |
| 월간 평가 관련 | 113/113 | 원예산·7봉투·정정·정책 변경·동시 수정·손상 자료의 409 |
| 자연어 조회 관련 | 76/76 | 표현 확장 전 실패 6건을 재현한 뒤 기존 계약과 함께 통과 |

| 앱 코칭(과거 실험, 현 MR 제외) | 고정 21 + 보관 GPU 응답 11 = 32/32 | 당시 응답 파싱·같은 세션의 저장 참조 복원; 새 GPU 추론으로 집계하지 않음 |
| 앱 클라이언트 → Spring → Python(과거 실험, 현 MR 제외) | 실제 HTTP 2/2 | 당시 원문 계약·재접속 참조. 주입 모델과 합성 인증 사용 |
| 정적 검사 | 통과 | Python src/tests Ruff·src basedpyright, 코칭 TypeScript/ESLint |

Python 전체 실행의 경고 1건은 Starlette 테스트 클라이언트가 AnyIO의 사용 중단 예정 별칭을 참조하는 의존성 경고다. 실패·건너뜀으로 바꾸어 집계하지 않았다. 독립 재검토에서 발견한 봉투 순서 오귀속, 관측 소비 함수 변경 누락, 저장 원예산 손상의 500 오류를 수정한 뒤 실행한 결과다.

전체 실행 뒤에는 제품 변경 없이 테스트 보조함수의 SQLite 연결을 명시적으로 닫았다. 해당 변경 후 관련 26/26과 실제 loopback TCP 6/6을 다시 통과했다. 이를 전체 813건에 더해 서로 독립된 사례 수처럼 표시하지 않는다.

현재 AI MR에서 제외된 당시 HTTP 원천 동기화 실험에서는 지출 **10,000 → 70,000 → 취소 후 10,000원**, revision 2와 중복 재전송의 `unchanged`를 확인했다. 동일 금액이라는 사실만 확인한 것이 아니라 원본 거래·취소와 비교한 연결 검사다. 테스트 모델의 연결 성공과 실제 GPU 모델 채택률, 미래 금액 정확도는 서로 다른 분모다.

### 새 패키지의 실제 GPU API 검증

독립 개발 API에 새 패키지를 설치하고 합성 소유자의 원문 질문 8개를 교체·강제 라우팅 없이 실행했다. **검사 73/73, 실제 HTTP 30건의 기대 상태 확인**이며 권한 위반·미성숙 정산의 의도한 거절도 포함한다. 같은 SQLite로 API를 실제 재시작한 후 답변 8개·세션·월별 등록·멱등 재시도의 원문이 일치했다. 월간 등록은 7봉투, 기준일 9월 14일, 미래 9월 15~30일의 16일이다. 아직 미래 월말에 도달하지 않은 등록을 실제 고객 만기 정산으로 표시하지 않았다.

| 원문 질문 | 응답 경로·작성 주체 | 응답 시간(초) |
| --- | --- | ---: |
| 복리의 이자가 다음 이자에 반영되는 이유를 알려줘. | 일반 금융·LLM | 3.615 |
| 그럼 조금 더 자세히 설명해 줘. | 같은 금융 주제·LLM | 3.708 |
| 이번 달 외식에 얼마 썼어? | 확정 소비·엔진 | 1.714 |
| 내 계좌 잔액은 지금 얼마야? | 개인 현황·엔진 | 0.974 |
| 이번 달 말까지 남을 현금을 예측해줘. | FDT 예측·LLM 설명 | 4.061 |
| 이번 달 말까지 위험을 분석해줘. | FDT 위험·LLM 설명 | 4.452 |
| 예금과 적금이 어떻게 다른지 설명해줘. | 일반 금융·LLM | 4.534 |
| 이번 달 외식 소비를 다시 확인해줘. | 확정 소비·엔진 | 1.909 |

경로 선택은 LLM 8/8, 최종 작성은 LLM 5건·의도한 엔진 응답 3건이며 예상 밖 fallback과 입력 초과 413은 0건이다. 소비 조회 두 응답은 합성 원장에서 별도로 확정한 2,000원과 일치했다. 일반 금융의 LLM 채택은 검색된 승인 근거 선택을 포함하며 자유 생성 답변의 전체 사실 정확도 점수는 아니다.

서버 내부 loopback에서 각 질문을 순서대로 1회 측정했다(n=8). 중앙값 **3.661초**, 평균 3.121초이며 외부 네트워크·모바일 지연·동시 부하·장시간 안정성은 측정하지 않았다. 기존 실행과 문항 집합이 달라 지연이 개선됐다고 비교하지 않는다.

실제 설명·라우팅 모델은 `Qwen/Qwen3.8-27B` NF4이며 기존 모델을 유지했다. 서비스의 유효 설정은 출력 256토큰, 동시 요청 제한 2, 제한시간 30초, 토큰 사전 검사 활성이다. 추론 워커 자체의 상한은 입력 8,192·출력 1,536토큰이며 sampling/thinking은 비활성이다. 수치 receipt는 팀 FDT의 `calendar-block-bootstrap/2.0`(경로 100개, seed 42, 이력 365일, `calibrated=false`)이다. 연구용 Chronos 후보를 이 API에 승격하지 않았다.

wheel SHA-256은 `d67db200c7437af47a49f30dc056059123e243ac6a9618362c7b2b4db8786089`다. 패키지 제품 파일 65개의 바이트와 엔진 21개·차트 6개 manifest가 일치했다. 교체 전 DB 백업·스키마 확인, 교체 후 기존 차트 14개 바이트 보존과 기존 추론 모델 프로세스의 식별값·정상 상태 유지를 확인했다. 운영 앱의 JWT/DB/FCM 배포와 구분한다.

다음 조건은 현재 AI MR에서 제외된 당시 외부 연동 실험에 해당한다. 원천 자동 동기화는 기본 비활성이었고, 최신 develop의 V1~V7과 통합한 뒤 V8 순서·충돌 확인이 필요했다. 직접 SQL/bulk 변경은 JPA 콜백을 거치지 않아 별도 enqueue 또는 대사가 필요했고, 현금 마감 관측이 없어 원천 어댑터의 snapshot은 `null`이었다. 해당 Spring·앱·마이그레이션 소스는 현재 AI MR에 포함되지 않는다.

검증 로그·원문 응답·가중치·거래 데이터는 `artifacts/` 등 비공개 위치에 보관하고 Git에는 실행 코드, 시험 코드, 재현 계약과 결과 설명만 올린다. MR 본문은 유지한다.
