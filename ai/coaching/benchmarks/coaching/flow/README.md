# 결제부터 대화·취소·재시작까지 검증

이 실행기는 **같은 사용자와 같은 대화 세션**을 유지한 채 HTTP API의 전체 흐름을 확인합니다.
매번 새 테스트 사용자·DB·임시 포트를 만들고 API 프로세스를 두 번 직접 실행합니다.
기존 서비스나 추론 워커의 프로세스를 종료하지 않습니다.

```powershell
# 로컬 전송·저장 계약 확인: 모델은 결정적인 시험용 구현입니다.
uv run python -m benchmarks.coaching.flow.run --backend fake --output artifacts/r14/flow/local

# 이미 설정된 GPU 추론 endpoint 사용: COACHING_MODEL 환경변수는 비공개로 주입합니다.
uv run python -m benchmarks.coaching.flow.run --backend gpu --output artifacts/r14/flow/gpu
```

`gpu` 실행은 모델 설정에 실제 endpoint가 있어야 시작합니다. 인증값을 인수나 파일 본문에
직접 적지 마세요. 실행기는 API용 인증을 메모리에서 생성하며 보고서에 보관하지 않습니다.
출력은 존재하지 않는 `artifacts/` 하위 디렉터리만 허용합니다. GPU 할당·워커 실행은 이 도구의
역할이 아니므로 서버의 기존 운영 절차에 따라 준비된 추론 endpoint만 사용합니다.

## 시험 순서

1. 관측일 이전 90일의 합성 거래와 관측일 계좌·봉투 잔액을 등록합니다.
2. 봉투 잔액의 절반인 50,000원 결제와 갱신된 계좌 스냅샷을 함께 전달합니다.
3. 생성된 코칭을 조회하고, 알림을 수신·확인 처리한 다음 그 코칭에 연결된 세션을 만듭니다.
4. 같은 세션에 복리 설명, 이번 달 말 잔액 예측, 이번 달 위험을 자연어로 질문합니다.
5. 12,000원 추가 거래와 스냅샷을 전달한 뒤 이번 달 확정 지출을 다시 질문합니다.
6. 첫 결제를 취소하고 환불 반영 스냅샷을 전달합니다. 지출·월말 예측·위험을 같은 세션에서 다시 질문합니다.
7. API 프로세스를 종료하고 같은 DB와 인증으로 새 프로세스를 실행합니다.
8. 세션·응답·Twin·미확인 알림을 다시 조회해 저장된 값과 비교합니다. 확인 처리한 알림과 결제·질문을
   같은 멱등성 키로 재전송해 중복 저장이나 잔액 변화가 없는지 확인합니다.

보고서 버전 `payment-chat-restart/2`부터 모든 assistant 메시지의 `response.kind`와 `response.id`가
해당 원문 응답과 정확히 연결되는지도 검사합니다. 원문 GET 결과·메시지 본문·재시작 전후 참조를 함께
비교하므로 본문 문자열만 저장하고 차트·근거·기간의 원본을 다시 찾지 못하는 상태는 통과하지 않습니다.

서버가 반환한 계산 함수로 정답을 만들지 않습니다. 기본 관측일 `2026-09-03`의 산술 기대값은
원시 합성 입력을 월별로 합산한 것입니다.

| 시점 | 봉투 잔액 | 관측 계좌 잔액 | 9월 확정 소비 |
|---|---:|---:|---:|
| 시작 | 100,000원 | 1,500,000원 | 2,000원 |
| 첫 결제 후 | 50,000원 | 1,450,000원 | 52,000원 |
| 추가 결제 후 | 38,000원 | 1,438,000원 | 64,000원 |
| 첫 결제 취소 후 | 88,000원 | 1,488,000원 | 14,000원 |

계좌 잔액은 거래액을 추정해 덮어쓰지 않고 이벤트와 함께 전달한 외부 확정 스냅샷을 확인합니다.
날짜 기대값은 Python 표준 달력으로 별도 계산하며, 9월 3일 마감 기준 예측은 9월 4일부터 9월 30일까지입니다.
추가 결제가 새 코칭 알림을 만들 수 있으므로 알림 개수를 무조건 0으로 기대하지 않습니다.
확인한 첫 알림은 미확인 목록에서 빠져야 하고, 남은 새 알림은 재시작 전후 동일해야 합니다.

## 결과 읽기와 한계

`report.json`에는 모든 HTTP 요청·응답, 검사별 결과, 질문별 실제 `wording_source`·모델명·fallback,
첫 프로세스의 종료 코드와 두 프로세스의 PID가 남습니다. `completed=true`는 모든 구조·금액·기간·저장
검사가 통과했다는 뜻입니다. HTTP 200만으로 성공으로 세지 않으며 예측 문장에 모델이 채택되었는지도 확인합니다.
`routing_observations`는 답변 writer와 별도로 라우터의 실제 source·fallback을 기록합니다. 예측과 확정 소비는
기본적으로 라우터의 `source=llm`과 fallback 부재까지 통과해야 합니다. 단, 명확한 개인 예측·위험 질문은
FDT 수치 계약이 있는 `forecast` 또는 `risk` 모드를 템플릿으로 결정할 수 있습니다. 이 경우
`source=template`, fallback 부재, 수치 계약을 함께 확인하며 이를 모델 채택으로 집계하지 않습니다. 금융 개념
응답처럼 서버가 routing metadata를 반환하지 않는 경우 `metadata_available=false`이며, 해당 라우터 호출의 모델
채택은 직접 확인한 것으로 세지 않습니다.
금융 개념 후 예측을 질문하거나 취소 후 현재 위험을 질문해도 기존 코칭과 현재 상태가 섞이지 않아야 합니다.

이 시험은 **합성 사용자 1명의 통합 회귀 시나리오**입니다. 99개 이상의 체크를 독립 고객 수나 예측 정확도
표본 수로 해석할 수 없습니다. `fake`에서 `wording_source=llm`은 시험용 주입 모델의 계약값이므로 실제 GPU
추론 증거가 아닙니다. `gpu`에서도 실제 고객의 미래 거래가 정답으로 제공되는 것은 아니며, 시장 금리·상품
추천·앱 UI·FCM 전달·부하 시험·장애 주입을 이 결과로 완료 처리하지 않습니다.

실행 코드는 이 폴더, 단위·TCP 회귀 검사는 `tests/test_flow_benchmark.py`, DB·로그·보고서는
git에서 제외되는 `artifacts/` 아래에 보관합니다.
