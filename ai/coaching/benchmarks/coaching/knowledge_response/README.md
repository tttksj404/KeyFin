# 금융 설명과 개인 조회 검증

이 실행기는 자연어 질문을 실제 TCP API에 보내고 응답·저장된 답변·세션 이력을 함께 확인합니다.
매번 새 사용자와 DB를 만든 격리 API 프로세스를 사용합니다. 기존 API와 추론 워커를 변경하지 않습니다.

```powershell
uv run python -m benchmarks.coaching.knowledge_response.run --backend fake --output artifacts/r14/knowledge_response/local
uv run python -m benchmarks.coaching.knowledge_response.run --backend gpu --output artifacts/r14/knowledge_response/gpu
```

`gpu`는 비공개 환경변수 `COACHING_MODEL`에 이미 설정된 추론 endpoint를 사용합니다.
`fake`는 고정된 시험용 모델을 주입하므로 GPU 추론 성능의 근거가 아닙니다.
출력은 존재하지 않는 `artifacts/` 하위 경로여야 합니다. 인증값은 결과 JSON에 저장하지 않습니다.

## 41개 질문의 구성

| 구분 | 질문 수 | 확인하는 내용 |
|---|---:|---|
| 금융 개념 | 27 | 질문의 승인 근거 ID, 실제 본문의 승인 문단·출처 일치, 금융 설명 응답, 모델 채택 |
| 범위 경계 | 3 | 최신 상품 금리는 추가 근거 필요, 비금융은 범위 밖, 미연결 개인 정보는 데이터 필요 |
| 같은 세션 후속 질문 | 2 | 복리 질문 후 “그럼 더 설명해줘.”에서 주제 유지와 메시지 저장 |
| 연결된 개인 조회 | 8 | 계좌·자산·부채·보험료·소득·고정비·예정 결제·목표의 독립 산술 기대값 |
| 지원하지 않는 필터 | 1 | 특정 은행 필터를 임의 적용하지 않고 추가 확인 요청 |

질문은 `cases.py`에 수동으로 고정했습니다. 금융 근거 파일의 별칭 문장을 그대로 가져오지 않았지만,
대부분 질문에 개념명을 포함합니다. 따라서 이 시험은 개발자가 만든 **합성 계약·주제 범위 회귀 검증**이며,
모르는 사람의 자유로운 질문 전체에 대한 이해도나 독립적인 정답 평가가 아닙니다. 과거 R13 질문 집합도 변경하지 않습니다.

## 개인 조회의 별도 정답

`fixtures.py`의 원시 입력에서 손으로 합산 가능한 금액을 사용합니다. 제품 계산 함수를 정답 생성에 사용하지 않습니다.

| 항목 | 기대값과 산식 |
|---|---|
| 계좌 | 1,320,000 − 20,000 = 1,300,000원 |
| 자산 | 계좌 1,300,000 + 비계좌 투자 250,000 = 1,550,000원 |
| 부채 | 대출 410,000 + 카드 미결제 90,000 = 500,000원 |
| 월 보험료 | 25,000 + 40,000 = 65,000원; 보장금액은 합산하지 않음 |
| 월 소득 | 2,800,000 + 250,000 = 3,050,000원 |
| 월 고정비 | 500,000 + 47,000 = 547,000원; 일부 항목만 제공한 상태 |
| 예정 결제 | 기준일 이후 18,000 + 72,000 = 90,000원 |
| 목표 | 목표별 저축액 150,000원과 250,000원을 각각 유지 |

기준일은 2026-09-03이며 예정 결제일은 9월 4일과 9월 8일입니다. 실제 FDT 입력 계약은
기준일보다 늦은 미결제 청구서만 허용하므로 당일·과거 청구서를 이 fixture에 넣지 않습니다.

## 결과 해석

`report.json`은 질문별 계약 통과 여부, HTTP 원문, 응답 writer와 router의 출처·fallback,
근거 파일 해시, API 종료 여부를 저장합니다. 근거 ID 일치는 올바른 승인 자료가 선택되었다는 증거입니다.
`knowledge-personal-coverage/3`은 실제 본문이 해당 승인 문단·출처와 같은지도 검사합니다.
ID만 맞는 빈 답변, 반대 의미의 본문, 승인되지 않은 문장 추가는 실패합니다.
부분 설명(`needs_source`)은 승인 문단과 검증되지 않은 부분을 알리는 고정 안내문을 함께 검사합니다.
이 검사는 **출처 충실도**이며 질문의 모든 핵심을 설명했는지, 출처 자체가 정확한지까지
입증하지 않습니다. 그 의미 평가는 별도 질문별 기준과 실제 답변 구절을 대조해야 합니다.
답변 전체의 의미 정확성·표현의 풍부함을 사람이 평가한 점수는 아닙니다.
`knowledge-personal-coverage/2`부터 41개 답변 각각의 세션 `response.kind`·`response.id`도 원본과
비교합니다. 기존 원본 GET 일치 검사와 결합해 재접속 화면이 올바른 출처·상태 자료를 다시 가져올 수 있는지 확인합니다.

`followup_text_changed`는 같은 세션의 두 설명이 달라졌는지를 별도로 기록합니다.
주제 유지에 성공해도 같은 설명이 반복될 수 있으므로, 이 값이 거짓이면 답변 심화가 확인된 것으로 보고하지 않습니다.
41개 질문 통과와 실제 고객의 금융 예측 정확도·최신 상품 정보 정확도는 별도 지표입니다.

실행 코드는 이 폴더, 검사는 `tests/test_knowledge_response.py`, 결과와 DB·로그는 git에서 제외되는
`artifacts/`에 보관합니다. 운영 시스템의 API 토큰이나 실제 개인 데이터를 결과에 넣지 마세요.
