# R15 사전 고정: 기간 합계를 직접 예측하는 실험 v2

모델 실행·새 정답 생성 전에 이 파일의 SHA256을 고정한다. 목표는 과거 공개 은행 자료의 7일/30일 **총 출금액** 오차 감소다. 한국 고객의 소비 봉투·잔액 예측과 다른 타깃이며 제품 FDT를 자동 교체하지 않는다.

v1 기본 모델의 7일 추론은 2,000건 중 1건의 분위수 역전으로 중단됐다. 정답·성능 점수는 열지 않았고 학습도 시작하지 않았다. v2는 이 입력 형식 문제에만 대응한다. 각 P10/P50/P90을 0 이상으로 제한한 다음 P50은 보존하고 `lower=min(P10,P50)`, `upper=max(P90,P50)`으로 구간을 넓힌다. NaN·무한값·잘못된 shape는 계속 거절하며, 역전 건수는 기록한다. 점 예측을 바꾸는 정렬이나 정답 기반 보정은 하지 않는다. 분할·후보·학습·선택·통과 기준은 v1과 동일하다. v1 자료와 실패 증거를 보존하고 v2 입력·프로토콜 해시를 별도로 고정한다.

## 기존 실험과 독립성

원자료는 R12와 동일한 PKDD'99 Berka이며 `public_bank.data.EXPECTED`의 두 원본 SHA256을 검증한다. 거래 분류·자료 수집 시점·미지원 type 계좌의 사후 제외·사전학습 포함 여부 불명의 한계도 R12와 같다. 실제 원장의 미래 합계를 정답으로 사용하며 예측 모델이나 FDT가 정답을 생성하지 않는다.

R12 계좌 순서의 처음 300개(개발/평가)는 모두 제외한다. 남은 계좌를 ASCII `berka-r15-v1:` + 원본 정수 계좌 ID의 SHA256으로 정렬한다. 처음 200개는 개발, 다음 200개는 보정, 다음 400개는 최종 평가, 나머지는 학습이다. 최소 801개가 필요하다. 계좌 간 중복은 거절한다. 이 새 평가 계좌의 1997년 이력은 R12 학습에 사용된 적이 있으므로 완전히 처음 보는 계좌라고 주장하지 않는다. **이번 최종 평가에 사용하는 1998년 미래 정답은 이전 R12 개발/평가에 사용되지 않았다.** R12 추가학습 가중치는 사용하지 않고 기록된 기본 체크포인트에서 새 학습을 시작한다.

학습: 학습 계좌의 1997-01-01~1997-12-31. 개발 기준일: 1998-01-31/03-31/05-31. 보정 기준일: 1998-06-30. 평가 기준일: 1998-07-31/09-30/11-30. 입력은 기준일까지 365일, 미래는 기준일 다음 날부터 7일 또는 30일이다. 같은 계좌의 여러 사례는 독립 표본이 아니며 통계는 계좌 단위로 재표집한다.

`model_inputs.json`에 과거 입력만 두고 세 정답 파일을 분리한다. GPU에는 정답을 보내지 않는다. 개발 선택 후 selection lock을 쓰고, 보정만 읽어 calibration lock을 쓴 다음 마지막 평가 명령만 평가 정답을 연다. 같은 출력 경로의 잠금/보고서는 덮어쓰지 않는다. 평가 결과를 본 뒤 수정하면 해당 평가는 회귀·탐색 자료가 되며 신규 독립 평가로 재포장하지 않는다.

## 고정 후보

비교 기준은 R12의 6개 단순 모델(28/90/365일 평균, 요일 혼합, 같은 일자 평균, 같은 일자/90일 평균 혼합) 중 **개발 MAE**가 가장 작은 모델이다.

새 산술 후보 5개:

1. 과거를 기준일에서 역방향으로 자른 겹치지 않는 h일 합계의 중앙값.
2. 같은 h일 합계의 양쪽 20% 절사 평균(최소 3블록).
3. 최근 6개 완전한 달의 일평균 소비를 월별로 구한 뒤 중앙값 × h.
4. 최근 6개 완전한 달에서 미래 달력상의 동일 일자별 출금 합계를 구한 월별 합계의 중앙값. 존재하지 않는 일자는 그 달의 말일로 중복 매핑하지 않고 생략하며, 관측된 일자 수로 h일에 비례 보정한다.
5. 위 동일 일자 중앙값과 90일 평균 모델의 50:50 혼합.

GPU 후보: Chronos-2의 과거 일별 값에 **후행 h일 합계**를 적용하고 h번째 미래 시점의 P10/P50/P90을 읽는다. 그 시점의 후행 h일 합계는 정확히 기준일 다음 날~h일 후의 총액이다. 일별 분위수를 합하지 않는다. h=7/30 각각 기본 모델과 새 full fine-tuning 2조건(128 optimizer steps, lr 1e-6 / 256 optimizer steps, lr 3e-6)을 비교한다. 각 학습은 새 base에서 시작, batch64/context365/min_past60/seed715, cross_learning=false, 다른 계좌의 미래 공변량 없음. 실제 optimizer 갱신 횟수와 변경된 가중치 해시를 기록한다. batch는 자원 부족 시 임의 축소하지 않고 실패·변경 실험으로 기록한다.

선택 후보는 위 14개 단일 후보(6+5+3)와, 3개 GPU 후보 각각에 대해 동일 일자 중앙값/90일 평균을 50:50 혼합한 6개로 총 20개다. 기간별 개발 MAE 최소, 동률은 이름 순이다. 시험 성능을 이용한 추가 배율 보정은 없다. 새 GPU 후보가 불완전하면 전체 실험 완료로 판정하지 않는다.

## 별도 구간 보정과 평가

기본 80% 구간: GPU 단일 후보는 합계타깃 P10/P90, 산술과 혼합 후보는 점값으로 시작한다. 보정 계좌에서 점/구간별 `max(lower-actual, actual-upper, 0) / max(point, recent90*h, 1 CZK)`를 계산하여 ceil((n+1)*0.8)번째 순서통계량으로 확장한다. 기준 모델도 같은 보정 규칙을 받는다. 확장 전후를 모두 보고한다. 계좌·시점 비정상성과 분할 가정 때문에 미래 서비스의 80% 보장을 주장하지 않는다.

평가 지표: MAE(CZK), WAPE, 예측−실제 편향, 80% 포함률·평균 구간 폭·WIS80. WIS80=(0.5*절대오차+0.1*(폭+10*구간 밖 거리))/1.5. 계좌 cluster bootstrap 2,000회/seed715의 paired MAE·WAPE 차이 95% 구간을 계산한다. 실제 금액 합계0이면 WAPE=null, 누락은 0으로 치환하지 않는다. 기간별·기준일별·과거 출금 크기별 악화도 보고한다. 개별 후보 시험 점수는 진단용이며 재선택하지 않는다.

연구 후보의 통과 조건(운영 SLA가 아님): 기간별 baseline 대비 MAE 10% 이상 감소, paired WAPE 차이 95% CI 상한<0, 보정 WIS 악화 없음, 각 기준일 MAE 악화5% 이하. 선택 모델이 baseline이면 개선 없음으로 기록한다. 기준을 넘지 못해도 결과를 보존한다. 이 실험 통과는 한국 실고객·7개 봉투·독립 인간 감사 완료를 의미하지 않는다.
